# BE-02 任务下达：卖家库存事务原子性

> 状态：已下达。开发团队必须先提交开发计划，PM Review 通过前不得改业务代码。

## 1. 目标

BE-02 的产品目标是让中小淘宝卖家完成一条可信的库存业务闭环：

1. 买入入库：`purchase_in` 增加指定商品、指定库位库存。
2. 卖出出库：`sales_out` 扣减指定商品、指定库位库存。
3. 库存流水：`inventory_movement` 记录每次库存变化，支持后续追溯。
4. 财务交易：库存变动和交易记录同事务提交或回滚。
5. 身份安全：业务端只使用 `puid`、`ouid`、`product_uid`、`location_path` 等业务字段，不暴露数据库数字主键。

## 2. 非目标

1. 不改变 BE-01 已验收的权限隔离规则。
2. 不做旧身份字段适配。
3. 不做字段迁移；如数据库结构需要变化，按当前规则重建表。
4. 不做大型前端改造。
5. 不把 `/resource-warehouse` 的直接写库存能力扩展为卖家业务入口。

## 4. API 契约草案

建议新增卖家事务 API，开发团队可在计划中论证最终路径：

### 买入入库

`POST /seller/purchase-in`

请求体：

```json
{
  "product_uid": "SKU-001",
  "quantity": 10,
  "location_path": "A-1-01",
  "unit": "件",
  "total_amount": 200.0,
  "counterparty_name": "供应商A",
  "note": "首次进货"
}
```

响应体不得包含数据库数字主键，建议：

```json
{
  "status": "ok",
  "operation": "purchase_in",
  "product_uid": "SKU-001",
  "location_path": "A-1-01",
  "quantity_delta": 10,
  "new_quantity": 10
}
```

### 卖出出库

`POST /seller/sales-out`

请求体：

```json
{
  "product_uid": "SKU-001",
  "quantity": 2,
  "location_path": "A-1-01",
  "unit": "件",
  "total_amount": 80.0,
  "counterparty_name": "买家A",
  "note": "订单发货"
}
```

响应体同样不得包含数据库数字主键。

## 5. 数据库与事务要求

开发团队计划中必须明确：

1. `inventory_movement` 表结构。
2. `execute_purchase_in(...)` 的事务边界。
3. `execute_sales_out(...)` 的事务边界。
4. 库存行锁策略，至少覆盖并发卖出同一商品同一库位。
5. 库存不足时的回滚策略。
6. 交易记录、参与方记录、库存流水、库存数量更新必须同事务。
7. 对外 DTO 必须剥离 `resource_id`、`warehouse_id`、`transaction_id`、`organization_id`、`person_id`。

## 6. 必测用例

开发团队计划至少覆盖以下 TDD：

| # | 用例 | 通过条件 |
|---|------|----------|
| 1 | 买入入库 | 库存增加，返回业务字段 |
| 2 | 卖出出库 | 库存减少，返回业务字段 |
| 3 | 库存不足卖出 | 返回 400/409，库存不变 |
| 4 | 买入事务失败 | 不产生半条交易、库存或流水 |
| 5 | 卖出事务失败 | 不产生半条交易、库存或流水 |
| 6 | 跨店铺访问 | 店铺 B 不能操作店铺 A 商品 |
| 7 | 库存流水追溯 | 能按商品和库位查到正负变动 |
| 8 | 无数据库主键泄漏 | API 响应不含内部主键字段 |
| 9 | BE-01 回归 | `test_seller_inventory_api.py` 仍通过 |
| 10 | 三国回归 | `test_three_kingdoms_http.py` 仍通过 |

## 8. PM Review 红线

以下任一情况出现，BE-02 不允许开工或合并：

1. 计划没有 TDD 红灯阶段。
2. 库存、交易、流水不是同事务。
3. 响应体出现数据库数字主键。
4. 接口需要前端传 `organization_id`、`person_id`、`resource_id`、`warehouse_id` 才能完成业务动作。
5. 出现旧身份字段适配方案。
6. 库存不足时仍写入交易或流水。
7. 未说明并发卖出的行锁策略。
