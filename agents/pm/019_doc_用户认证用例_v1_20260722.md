# 用户认证用例

> 角色：项目经理
> 状态：已按单账号多空间模型修订，待开发实现
> 范围：用户注册、用户登录、组织列表、组织切换
> 约束：`account` 保存登录凭据，`person` 保存业务人员身份，`membership` 保存组织授权，`organization` 是业务空间数据边界。

---

## 0. PM 决策

1. 登录账号不再携带组织上下文，废弃 `puid@ouid` / `puid@ouid.cn` 作为登录格式。
2. `account.login` 与 `person.puid` 不做物理归并：
   - `account.login` 是认证凭据，唯一，可为 `zhansan`、邮箱或手机号等。
   - `person.puid` 是业务人员标识，唯一，必须保持英文安全字符。
3. MVP 演示用户可以让二者取同一个值：`account.login = "zhansan"`，`person.puid = "zhansan"`。
4. 一个账号登录后，通过 `membership(person_id, organization_id)` 获得可进入的多个业务空间。
5. 空间切换只能通过 `/auth/switch-organization` 重新签发 JWT，前端不得自行改 `ouid`。
6. 用户注册必须支持创建 `account + person`，可选加入一个初始组织；未加入组织时进入“暂无业务空间”状态。
7. 认证、注册、切换组织的请求和响应都不得暴露数据库数字 ID，不得恢复 `pid/oid` 兼容。

---

## 1. 数据模型约定

### person

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | integer | 数字主键，仅服务端/数据库内部使用 |
| `puid` | varchar | 业务人员标识，唯一，英文安全字符，例如 `zhansan` |
| `name` | varchar | 展示名，例如 `张三` |

`person` 表示真实业务人或业务身份，不保存密码，不保存登录态。

### account

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | integer | 数字主键，仅服务端/数据库内部使用 |
| `person_id` | integer | 外键，指向 `person.id` |
| `login` | varchar | 登录凭据，唯一，例如 `zhansan` |
| `password` | text | 密码哈希，禁止明文存储 |
| `salt` | text | 密码盐；如使用 Argon2 encoded hash，可为空 |
| `status` | varchar | 账号状态，默认 `active` |
| `system_role` | varchar | 系统级角色，默认 `user`，超级用户为 `super` |
| `created_at` | timestamp | 创建时间 |
| `updated_at` | timestamp | 更新时间 |

说明：`account.login` 是认证入口，不是组织上下文。即使未来允许邮箱或手机号登录，也不能从 login 中解析 `ouid`。

### organization

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | integer | 数字主键，仅服务端/数据库内部使用 |
| `ouid` | varchar | 组织/业务空间标识，唯一，英文安全字符，例如 `zhansan_shop` |
| `name` | varchar | 展示名，例如 `张三小店` |
| `type` | varchar | 空间类型，例如 `ecommerce` / `family` / `campaign` / `starship` |

当前 MVP 不新增 `workspace` 表，继续用 `organization.type` 表示业务形态。

### membership

| 字段 | 说明 |
|------|------|
| `person_id` | 数字外键，指向 `person.id` |
| `organization_id` | 数字外键，指向 `organization.id` |
| `role` | 用户在组织中的角色，例如 `owner` / `admin` / `member` / `viewer` |

`membership` 是“人进入哪个业务空间、在该空间拥有什么角色”的唯一授权来源。

---

## 2. 字段命名约定

- `person.id`：人员数字主键，仅服务端内部使用。
- `person.puid`：人员业务标识，字符串，例如 `zhansan`。
- `organization.id`：组织数字主键，仅服务端内部使用。
- `organization.ouid`：组织业务空间标识，字符串，例如 `zhansan_shop`。
- 除 `person` / `organization` 两张主表外，其他表的外键统一使用 `person_id` / `organization_id`。
- JWT payload 只能出现 `puid`、`ouid`、展示名、组织类型、系统角色、组织角色等业务字段，不得出现 `id`、`person_id`、`organization_id`。

---

## 3. 登录名与上下文规则

### 3.1 登录名

新登录名规则：

```text
account.login
```

示例：

```text
zhansan
```

`login` 不再解析为 `puid` 和 `ouid`。以下旧形式不得作为空间选择机制：

```text
zhansan@zhansan_shop
zhansan@fire_xinye_shu
zhansan@zhangsan_family
zhansan@deep_space_fleet
```

如果未来允许邮箱作为 `account.login`，例如 `zhangsan@example.com`，也只能作为账号凭据，不能把 `@` 后面的内容解释成组织。

### 3.2 person.puid

注册时 `puid` 的来源：

1. 请求体显式传 `puid`：按 `^[A-Za-z0-9_-]+$` 校验。
2. 请求体未传 `puid`，且 `login` 本身满足 `puid` 规则：默认 `puid = login`。
3. 请求体未传 `puid`，且 `login` 不满足 `puid` 规则：返回 422，要求用户补充英文安全 `puid`。

### 3.3 当前业务空间

当前业务空间来自 JWT 中的 `ouid`，JWT 只能由服务端根据 membership 签发：

1. 登录成功后，服务端为用户选择一个默认空间并签发 JWT。
2. 前端调用 `/auth/me/organizations` 获取该 person 拥有的空间列表。
3. 用户切换空间时，前端调用 `/auth/switch-organization`，只提交目标 `ouid`。
4. 后端校验 `membership(person_id, organization_id)` 后重新签发 JWT。
5. 前端保存新 token 后刷新 Header、Sidebar 和 Main。

默认空间选择规则建议：

1. 如账号后续增加 `last_ouid` 或用户偏好，则优先使用。
2. MVP 暂无偏好字段时，按服务端稳定顺序选择第一个 active membership。
3. 登录接口不得通过解析 `login` 选择空间。

## 4. 用例一：用户注册

### 目标

新用户注册后创建 `account + person`，并可选加入一个初始组织空间。

### API

```http
POST /auth/register
```

### Request

```json
{
  "login": "zhansan",
  "password": "demo-password",
  "name": "张三",
  "puid": "zhansan",
  "initial_ouid": "zhansan_shop"
}
```

字段说明：

| 字段 | 必填 | 说明 |
|------|------|------|
| `login` | 是 | 账号登录凭据，唯一，不解析组织 |
| `password` | 是 | 用户密码，后端只保存哈希 |
| `name` | 是 | 展示名 |
| `puid` | 否 | 业务人员标识；缺省时可由安全 login 推导 |
| `initial_ouid` | 否 | 初始加入组织；缺省则注册为暂无空间用户 |

### 业务流程

1. 校验 `login` 非空且唯一；不得把 `login` 解析成 `ouid`。
2. 根据 §3.2 决定 `puid`，并校验英文安全字符。
3. 查询 `person.puid = puid`：
   - 不存在：创建 person。
   - 已存在：仅允许与同一个 account 绑定；公共注册不得抢占他人 puid。
4. 创建 `account`：
   - `person_id = person.id`
   - `login = request.login`
   - `password` 使用 Argon2 encoded hash；如 Argon2 接入困难，允许临时使用 bcrypt。
   - `system_role = user`
5. 如传 `initial_ouid`：
   - 查询 `organization.ouid = initial_ouid`。
   - 不存在返回 404。
   - 创建 `membership(person_id, organization_id, role="member")`。
   - 公共注册不得授予 `owner`、`admin`、`super`。
6. 如未传 `initial_ouid`：
   - 不创建 membership。
   - 返回 `requires_organization = true`，前端进入“创建/加入空间”占位流程。
7. 返回注册结果。响应只含业务字段，不含 DB 数字 ID。

### Response

加入初始组织时：

```json
{
  "access_token": "...",
  "token_type": "bearer",
  "person": {
    "puid": "zhansan",
    "name": "张三"
  },
  "organization": {
    "ouid": "zhansan_shop",
    "name": "张三小店",
    "type": "ecommerce"
  },
  "account": {
    "login": "zhansan",
    "status": "active",
    "system_role": "user"
  },
  "membership": {
    "role": "member"
  },
  "requires_organization": false
}
```

未加入组织时：

```json
{
  "access_token": null,
  "token_type": null,
  "person": {
    "puid": "newuser",
    "name": "新用户"
  },
  "account": {
    "login": "newuser",
    "status": "active",
    "system_role": "user"
  },
  "organizations": [],
  "requires_organization": true
}
```

### 验收标准

- `login=zhansan` 注册成功，创建 `account.login=zhansan` 和 `person.puid=zhansan`。
- `login=zhansan@zhansan_shop` 不得被解析成 `ouid=zhansan_shop`。
- 注册请求带 `initial_ouid=unknown_space` 返回 404。
- `puid=张三` 返回 422。
- 重复 `account.login` 返回 409。
- 公共注册请求 `role=owner/admin/super` 不得生效。
- 注册成功响应无 `id`、`person_id`、`organization_id`。
- 密码只允许以哈希形式进入 `account.password`，不允许写入 `person`。

## 5. 用例二：用户登录

### 目标

用户通过单一 `account.login` 和密码登录，系统返回当前默认空间上下文，并允许用户随后切换到其他 membership 空间。

### API

```http
POST /auth/login
```

### Request

```json
{
  "login": "zhansan",
  "password": "demo-password"
}
```

### 业务流程

1. 查询 `account.login = request.login`；不存在返回 401。
2. 确认 `account.status = active`，否则返回 403。
3. 校验 `account.password`，失败返回 401。
4. 通过 `account.person_id` 查询 person。
5. 查询该 person 的 active membership 列表。
6. 如果无 membership：
   - 返回 `requires_organization = true`。
   - 不签发组织上下文 JWT。
7. 如果有 membership：
   - 按 §3.3 选择默认组织。
   - 签发带当前 `puid/ouid` 的 JWT。
   - 返回当前组织、当前 membership 和全部可切换组织列表。

### JWT payload

JWT 只放业务字段，不夹杂数据库数字主键。

```json
{
  "puid": "zhansan",
  "person_name": "张三",
  "ouid": "zhansan_shop",
  "organization_name": "张三小店",
  "organization_type": "ecommerce",
  "system_role": "user",
  "role": "owner"
}
```

### Response

```json
{
  "access_token": "...",
  "token_type": "bearer",
  "person": {
    "puid": "zhansan",
    "name": "张三"
  },
  "organization": {
    "ouid": "zhansan_shop",
    "name": "张三小店",
    "type": "ecommerce"
  },
  "account": {
    "login": "zhansan",
    "status": "active",
    "system_role": "user"
  },
  "membership": {
    "role": "owner"
  },
  "organizations": [
    { "ouid": "zhansan_shop", "name": "张三小店", "type": "ecommerce", "role": "owner" },
    { "ouid": "fire_xinye_shu", "name": "火烧新野-蜀汉", "type": "campaign", "role": "owner" },
    { "ouid": "zhangsan_family", "name": "张三家庭", "type": "family", "role": "owner" },
    { "ouid": "deep_space_fleet", "name": "深空远航舰队", "type": "starship", "role": "owner" }
  ],
  "requires_organization": false
}
```

### 验收标准

- `zhansan / 正确密码` 登录成功，返回默认空间 JWT 和 4 个可切换空间。
- `zhansan / wrong` 登录失败，返回 401。
- `account.status != active` 登录失败，返回 403。
- `zhansan@fire_xinye_shu / 正确密码` 不得作为组织切换方式。
- 登录响应和 JWT 均无 DB 数字 ID。
- 登录成功后，前端上下文必须来自 token 和 `/auth/me/organizations`，不能手动访问未授权组织。

## 6. 用例三：查询可切换组织

### API

```http
GET /auth/me/organizations
```

### 业务流程

1. 从 JWT 读取 `puid`。
2. 查询 `person.puid`。
3. 查询该 person 的 membership 列表。
4. 返回可切换组织列表，只含 `ouid/name/type/role`。
5. 不接受 `puid`、`ouid`、`id`、`*_id` 查询参数。

### Response

```json
[
  { "ouid": "zhansan_shop", "name": "张三小店", "type": "ecommerce", "role": "owner" },
  { "ouid": "zhangsan_family", "name": "张三家庭", "type": "family", "role": "owner" }
]
```

## 7. 用例四：切换组织空间

### API

```http
POST /auth/switch-organization
```

### Request

```json
{
  "ouid": "zhangsan_family"
}
```

### 业务流程

1. 从当前 JWT 读取 `puid`。
2. 查询目标 `organization.ouid`。
3. 校验 `membership(person_id, organization_id)`。
4. 校验通过后重新签发目标空间 JWT。
5. 返回与登录一致的上下文 DTO。

### 验收标准

- `zhansan` 可从 `zhansan_shop` 切到 `fire_xinye_shu`、`zhangsan_family`、`deep_space_fleet`。
- 非 membership 组织返回 403。
- 组织不存在返回 404。
- 请求只接受业务字段 `ouid`，不得接受 `organization_id`。
- 响应无 DB 数字 ID。

## 8. 开发任务

### Backend

1. `src/models/schemas.py`
   - `RegisterRequest` 增加 `puid: Optional[str]`、`initial_ouid: Optional[str]`。
   - `LoginRequest.login` 注释改为账号凭据，不再写 `puid@ouid`。
   - 所有 auth 请求模型启用 `extra = "forbid"`。
2. `src/auth/auth.py`
   - 移除 `parse_login_name()` 作为认证入口。
   - 保留 `validate_puid()`、`validate_ouid()`。
   - 新增 `derive_puid_from_login(login)` 辅助函数，仅在 login 满足 puid 规则时用于注册缺省。
3. `src/routers/auth.py`
   - 登录按 `account.login` 查 account，不解析 `ouid`。
   - 注册按 §4 流程实现。
   - 登录返回可切换组织列表。
   - `/seller-login` 与 `/auth/login` 收口到同一认证逻辑；如保留路由，也不得要求 `login` 携带 `ouid`。
4. `src/db/database.py`
   - 增加“按 account.person_id 列 membership 并返回业务字段”的稳定查询。
   - 如需要默认空间，内部排序可用 DB 主键，但不得返回。
5. `scripts/seed_demo_spaces.py`
   - 只创建一个 `account.login=zhansan`。
   - 不再创建 `zhansan@<ouid>` 多账号。
   - 继续从 `DEMO_ZHANSAN_PASSWORD` 或未提交 `.env` 读取密码。

### Frontend

1. 登录页占位从 `puid@ouid` 改为 `zhansan`。
2. 登录成功后读取返回的 `organizations`，Header 展示可切换空间。
3. 如果 `requires_organization=true`，进入“创建/加入空间”占位页，不调用 Seller 或 spaces 业务接口。
4. 注册入口本期可为简单表单：
   - login
   - password
   - name
   - puid（可选）
   - initial_ouid（可选）
5. 前端不得构造 `zhansan@ouid` 形式来切换组织。

## 9. 禁止事项

1. 禁止恢复 `pid/oid`。
2. 禁止在登录名中解析组织上下文。
3. 禁止为同一个人创建 `zhansan@space` 这类多账号来模拟空间切换。
4. 禁止在业务响应、JWT、前端状态中暴露 DB 数字 ID。
5. 禁止公共注册授予 `owner/admin/super`。
6. 禁止把演示密码、JWT secret、DB 密码写入源码或可提交文档。
