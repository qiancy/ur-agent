# BE-04 开发计划：卖家经营查询前端 / 只读 AI 闭环

> 角色：产品经理 / 项目经理批准版  
> 前置：BE-01、BE-02、BE-03 已完成并通过 PM Review  
> 主题：前端查看库存、流水、经营摘要；AI 只能做 Seller 安全只读查询；自然语言查询库存、低库存、销售收入、采购支出；继续不向业务端暴露数据库数字主键。  
> 结论：原开发计划方向可用，但范围需要收敛。本轮 BE-04 不做 AI 写入库存，不引入写入开关。AI 写入能力必须等后续“确认流 + 审计 + 防误操作”设计完成后单独立项。

---

## 1. 目标和非目标

### 1.1 目标

1. 在现有 Gradio 前端 `src/frontend.py` 中，为 ecommerce 组织提供 Seller 工作区：库存、库存流水、经营摘要、Seller AI 助手。
2. 新增 `POST /seller/chat`，使用 strict JWT，只允许当前登录店铺上下文，不能通过请求参数或请求体切换店铺；API 层必须校验当前组织 `org_type == "ecommerce"`，非 ecommerce 组织直接返回 403。
3. 新增 Seller 只读 AI 工具集，支持自然语言查询：
   - 当前库存。
   - 低库存商品。
   - 销售收入。
   - 采购支出。
   - 商品维度经营汇总。
   - 库存流水。
4. AI 工具签名只接受业务查询参数，不接受身份参数、数据库数字主键或任何内部上下文字段。
5. 前端和 AI 响应都不得出现数据库数字主键字段。
6. 不破坏 BE-02 事务函数、BE-03 Seller 查询端点、三国演示和旧 `/chat`。

### 1.2 非目标

1. 不做 AI 采购入库、销售出库、盘点、调拨等写操作。
2. 不做写入开关；本轮不存在 AI 写工具。
3. 不改旧通用 `/chat`，不重构旧通用工具。
4. 不治理旧通用 Resource、Party、Transaction API 的数据库数字主键暴露；该问题进入独立技术债 BE-TD-01。
5. 不做前端多店铺切换、图表大屏、订单同步、退款退货、库存预警通知。
6. 真实 LLM 不进自动化测试；CI 使用工具层测试和 mock LLM 测试。

## 2. 产品原则

1. BE-04 是“查询闭环”，不是“AI 经营执行”。
2. Seller AI 默认且只能只读。用户问“帮我入库/卖出/修改库存”时，AI 应明确说明当前版本只支持查询，并引导用户使用现有人工 HTTP/前端写入路径。
3. 所有店铺上下文只来自 Bearer JWT。
4. 业务端只看业务字段：`product_uid`、`warehouse_code`、`location_path`、`movement_uid`、`operation_type`、`quantity_delta`、`new_quantity`、`unit`、`total_amount`、`counterparty_name`、摘要字段。
5. BE-04 新增代码、测试、文档中不得固化旧二字母身份键。

## 3. AI 工具契约

### 3.1 工具工厂

新增 `src/tools/seller_tools.py`：

```python
def make_seller_tools(shop_key: int) -> list:
    ...
```

说明：

1. `shop_key` 是后端从 JWT 解析出的内部组织主键，只在闭包中使用，作为内部 DB 位置参数传入（如 `query_stock(shop_key, ...)`），不暴露给模型、不出现在工具 schema。
2. 工具签名不包含任何身份参数、裸 `id` 参数或 `*_id` 参数。
3. 工具只读，不包含采购入库、销售出库、创建、更新、删除类能力。
4. 工具输出统一使用 JSON 文本：`json.dumps(..., ensure_ascii=False, default=str)`。
5. 工具异常统一返回安全错误文本，不泄漏 SQL、连接串、堆栈或内部字段。

### 3.2 只读工具清单

| 工具名 | 入参 | 底层函数 | 说明 |
|---|---|---|---|
| `seller_stock` | `product_uid: str | None = None` | `query_stock` | 查询当前库存 |
| `seller_summary` | `date_from=None, date_to=None, low_stock_threshold=5, top_n=5` | `get_seller_summary` | 查询经营摘要、低库存、热销 |
| `seller_product_summary` | `product_uid=None, date_from=None, date_to=None` | `query_product_summary` | 查询商品经营汇总 |
| `seller_inventory_movements` | `product_uid=None, operation_type=None, date_from=None, date_to=None, limit=None, offset=0` | `query_inventory_movements` | 查询库存流水 |

### 3.3 工具红线

1. 工具列表不得引用 `src.tools.ALL_TOOLS`。
2. 工具列表不得包含旧通用工具。
3. 工具参数不得包含身份字段、裸 `id`、或任何 `*_id`。
4. 工具输出递归不得包含数据库数字主键字段。
5. 工具不得调用 BE-02 写入函数。
6. 内部实现允许用 `shop_key` 作位置参数调用 DB 函数；`shop_key`、`organization_id`、`person_id` 等内部字段只允许在闭包/服务端内部使用，不得出现在工具 schema、工具输出或任何请求/响应契约中。

## 5. API 契约：`POST /seller/chat`

### 5.1 请求

```http
POST /seller/chat
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
{
  "message": "帮我看一下今天卖了多少钱"
}
```

请求体只允许 `message` 一个字段。出现额外字段必须返回 `422` 或 `400`。

实现要求：

1. 新增独立请求模型 `SellerChatRequest`，不得复用现有通用 `ChatRequest`。
2. `SellerChatRequest` 只包含 `message: str`。
3. `SellerChatRequest` 必须设置 `model_config = {"extra": "forbid"}`。
4. `message.strip()` 为空时必须返回 422。

### 5.2 响应

```json
{
  "response": "今天销售收入为 45.00 元，采购支出为 80.00 元，净现金流为 -35.00 元。",
  "ouid": "taobao_shop_a"
}
```

响应不得包含数据库数字主键字段，不返回 intermediate steps。

### 5.3 校验与错误

| 场景 | 状态码 | 要求 |
|---|---:|---|
| 无 Bearer token | 401 | 必须拒绝 |
| JWT 无效 | 401 | 必须拒绝 |
| JWT 缺少 `puid` 或 `ouid` | 401 | 必须拒绝 |
| 非当前组织成员 | 403 | 必须拒绝 |
| 当前 JWT 组织不是 ecommerce | 403 | 必须拒绝 |
| query 参数含身份字段、裸 `id`、或 `*_id` | 400/422 | 必须拒绝 |
| body 含身份字段、裸 `id`、或 `*_id` | 400/422 | 必须拒绝 |
| `message` 为空或全空白 | 422 | 必须拒绝 |
| LLM 超时 | 504 | 返回安全错误 |
| LLM 异常 | 502/503 | 返回安全错误，不泄漏内部异常 |

`org_type` 校验数据来源：扩展 `src/routers/deps.py` 的 `_build_context`，增加 `org_type`、`org_name` 两个键（从组织记录读取，与 `require_org_context` 同口径，见 deps.py 现有 org_type 用法）。ecommerce 校验只信任 JWT 解析出的 `org_type`，不得信任请求参数。`organization_id` / `person_id` 仍只在服务端内部使用，不得返回业务端。

### 5.4 身份快路径

`"我是谁"`、`"当前空间"`、`"当前店铺"` 等问题可直接由后端回答，响应只包含业务身份和组织名称，例如：

```json
{
  "response": "当前店铺：淘宝小店 A，组织标识：taobao_shop_a，当前用户：seller_a。",
  "ouid": "taobao_shop_a"
}
```

组织名取自扩展后 `_build_context` 返回的 `org_name`（不额外查库）；不得返回内部主键。

### 5.5 写入意图路由级拒绝

`/seller/chat` 在进入 LLM 前必须做写入意图拦截。拦截规则采用**写入动词短语 + 只读意图排除**，不能只按单个词粗暴匹配，否则会误伤「采购支出是多少」「看出库流水」等合法只读查询。

1. **写入动词短语命中**（命中以下任一项，进入判定）：
   - 帮我入库 / 帮我采购入库 / 帮我进货
   - 帮我出库 / 帮我卖出 / 帮我卖
   - 帮我买（指代采购库存，非查询）
   - 修改库存 / 调整库存 / 改库存
   - 创建 / 新增 / 删除 / 记录一笔（指代业务记录时）
2. **只读意图排除**：消息同时包含以下只读名词之一时，放行为查询，不得拦截：
   - 支出 / 流水 / 统计 / 查询 / 列表 / 金额 / 汇总 / 余额 / 多少
   - 例：「采购支出是多少」「看出库流水」「入库金额统计」均进入查询链路。
3. 命中写入意图时，直接返回只读说明，不调用 LLM、不调用任何工具：

```json
{
  "response": "当前版本的 Seller AI 只支持经营查询，不能代你执行入库、出库、修改库存或创建记录。请使用人工操作入口完成写入。",
  "ouid": "taobao_shop_a"
}
```

该拦截是产品安全边界，不依赖 LLM 自觉遵守。

## 6. 前端设计

### 6.1 显示规则

1. 登录组织 `org_type == "ecommerce"` 时显示 Seller tabs。

第三条不得命中。

## 10. Review 红线

以下任一情况出现，BE-04 不允许合并：

1. `/seller/chat` 可匿名访问。
2. 可通过 query/body 参数切换店铺上下文。
3. `/seller/chat` 请求体允许 `message` 以外字段静默通过。
4. Seller AI 工具签名接受身份参数、裸 `id`、或任何 `*_id`。
5. Agent 挂载旧通用工具或 `ALL_TOOLS`。
6. Seller Agent 调用远程 prompt hub。
7. 工具集合包含写入能力。
8. 工具或 `/seller/chat` 输出暴露数据库数字主键字段。
9. 新增代码、测试、文档中出现旧二字母身份键。
10. 写入意图进入 LLM 或被 AI 执行，而不是在路由层明确拒绝。
11. LLM 超时或异常以 500 泄漏内部细节。
12. 非 ecommerce 组织可以调用 `/seller/chat`（ecommerce 校验必须基于 JWT 解析出的 `org_type`，不得信任请求参数）。
13. 破坏 BE-02 入库/出库事务函数。
14. 破坏 BE-03 Seller 查询端点默认契约。
15. 前端 Seller tabs 对非 ecommerce 组织可见。
16. 前端 Seller API 请求继续拼接店铺上下文查询参数，而不是只使用 Bearer JWT。
