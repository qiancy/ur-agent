# BE-04 收尾开发安排：卖家经营查询前端 / AI 闭环

> 角色：产品经理 / 项目经理下达  
> 日期：2026-08-02  
> 前置：配置治理任务提交后执行；BE-04 主体设计见 `agents/pm/BE-04_开发计划.md`  
> 目标：完成 Seller 查询闭环，并执行比赛交付前安全扫描。

## 1. 本轮目标

1. 前端能查看库存、库存流水、经营摘要。
2. Seller AI 只能调用安全只读 Seller 工具。
3. 自然语言可查询当前库存、低库存、销售收入、采购支出。
4. 请求、响应、前端展示、AI 工具 schema 均不得暴露数据库数字 ID。
5. 默认自动化测试不得触发真实 LLM。

## 2. 工作分工

### 2.1 Frontend

负责人：Frontend

范围：

1. 在 `src/frontend.py` 完成 Seller 工作区收尾。
2. ecommerce 登录后显示 Seller 区域；非 ecommerce 组织不显示。
3. Seller 区域至少包含：
   - 库存：调用 `GET /seller/stock`。
   - 流水：调用 `GET /seller/inventory-movements`，支持操作类型、日期、limit。
   - 摘要：调用 `GET /seller/summary`。
   - Seller AI：调用 `POST /seller/chat`。
4. 所有 Seller API 请求只带 Bearer token，不拼接 `puid`、`ouid`、`id`、`*_id` 查询参数。
5. 前端展示字段只允许业务字段：`product_uid`、`warehouse_code`、`location_path`、`quantity`、`quantity_delta`、`new_quantity`、`unit`、`operation_type`、`movement_uid`、金额/摘要字段。

验收：

1. ecommerce 账号登录后可看到 Seller tabs。
2. 三国 / company / system 组织不显示 Seller tabs。
3. Seller 页面无 `id`、`organization_id`、`person_id`、`resource_id`、`warehouse_id` 等字段展示。
4. 刷新库存、流水、摘要均可工作。

### 2.2 Backend / AI

负责人：Backend

范围：

1. 确认 `src/tools/seller_tools.py` 只暴露 Seller 只读工具：
   - `seller_stock`
   - `seller_summary`
   - `seller_product_summary`
   - `seller_inventory_movements`
2. 工具签名不得包含身份字段、裸 `id`、或任何 `*_id`。
3. 工具输出递归不得包含数据库数字主键字段。
4. `src/agents/seller_agent.py` 只接受显式 Seller 工具列表，不得挂载 `ALL_TOOLS`。
5. Seller Agent 不调用 `hub.pull()` 或远程 prompt hub。
6. `/seller/chat` 必须 strict JWT，只允许 ecommerce 组织。
7. `/seller/chat` 写入意图在路由层拒绝，不进入 LLM。
8. 「采购支出是多少」「销售收入多少」「低库存有哪些」「库存流水」等只读问题不得被写入拦截误伤。

验收：

1. 匿名 `/seller/chat` 返回 401。
2. 非 ecommerce JWT 调用 `/seller/chat` 返回 403。
3. query/body 含 `puid`、`ouid`、`id`、`*_id` 返回 400/422。
4. Seller AI 工具集合不含写工具、不含通用工具。
5. 默认测试不调用真实 LLM。

### 2.3 TDD / QA

负责人：TDD

范围：

1. 补齐或复核 `agents/tdd/test_seller_ai_tools.py`。
2. 补齐或复核 `agents/tdd/test_seller_chat_api.py`。
3. 如前端新增可测试 helper，补最小单元测试；不要求 Gradio E2E。
4. 回归 BE-02/BE-03 Seller 核心测试。
5. 执行比赛前安全扫描并出具结果。

验收：

1. Seller 工具层测试绿色。
2. `/seller/chat` API 测试绿色。
3. BE-02/BE-03 Seller 查询和事务核心测试绿色。
4. 安全扫描无 P0 命中。

## 3. 实施顺序

1. Frontend 复核 `src/frontend.py` Seller tabs 显示、刷新、AI 对话、无 DB ID 展示。
2. Backend 复核 Seller tools / Seller Agent / `/seller/chat` 的只读边界。
3. TDD 先跑现有 BE-04 测试，缺口再补测试。
4. 修复测试失败。
5. 执行交付前安全扫描。
6. 开发团队提交实现报告，PM review 后允许合并。

## 5. 比赛交付前安全扫描

### 5.1 明文密钥扫描

```bash
rg -n "unires_secure_pass_2024|unires-dev-jwt-secret|rc-[A-Za-z0-9]{20,}" . \
  --glob '!*.pyc' \
  --glob '!__pycache__/**' \
  --glob '!.git/**' \
  --glob '!.pytest_cache/**' \
  --glob '!output/**'
```

验收：零命中。

### 5.2 `puid` / `ouid` 身份字段扫描

```bash
rg -n '"pid"|"oid"|pid=|oid=' src agents/tdd docs README.md
```

验收：

1. `pid` / `oid` 旧身份键零命中。
2. `puid` / `ouid` 允许作为业务身份字段出现。
3. 数据库迁移说明中的历史旧列名若必须保留，需 PM 单独确认。

### 5.3 DB 数字 ID 对外响应扫描

```bash
rg -n '"id"|[A-Za-z_]+_id|organization_id|person_id|resource_id|warehouse_id|transaction_id|inventory_movement_id' \
  src/routers/seller.py src/tools/seller_tools.py src/agents/seller_agent.py src/frontend.py agents/tdd/test_seller_ai_tools.py agents/tdd/test_seller_chat_api.py
```

验收：

1. 请求/响应 DTO、工具 schema、工具输出、前端展示不得暴露数据库数字 ID。
2. 服务端内部变量和闭包内部 `shop_key` 可人工 review 放行。
3. 测试中的禁止字段集合可人工 review 放行。

### 5.4 默认测试不触发真 LLM

```bash
env -u LLM_API_KEY -u JWT_SECRET python3 -m pytest agents/tdd/test_seller_chat_live_llm.py -q
env -u LLM_API_KEY -u JWT_SECRET python3 -m pytest agents/tdd/test_seller_chat_api.py -q
```

验收：

1. 第一条应 deselect 或 skip，不允许调用真实 LLM。
2. 第二条必须绿色，且只使用 mock LLM。

## 6. PM 红线

以下任一出现，本轮不允许合并：

1. 前端或 AI 响应出现数据库数字 ID。
2. Seller AI 挂载 `ALL_TOOLS` 或通用写工具。
3. 写入意图进入 LLM。
4. 非 ecommerce 组织可见或可调用 Seller AI。
5. 默认测试调用真实 LLM。
6. 仓库出现真实 DB 密码、JWT secret、AMD API Key。
7. 新增代码或文档重新引入 `pid` / `oid` 旧身份键。
