# PERF-01 数据库连接池与首屏聚合加载开发规格书

> 角色：项目经理 / 产品经理
> 目标：解决 Demo 录屏中“数据加载慢、加载后页面停留/等待感明显”的体验问题。
> 范围：MVP 性能优化；不改业务语义、不改 DB schema、不引入大型 ORM。
> 优先级：P0，比赛录屏前完成。
> 当前状态：规格已完善并按本规格完成首轮实现；远程 Demo 环境性能实测仍需录屏前补报告。

## 1. 背景与问题判断

### 1.1 当前事实

当前 `src/db/database.py` 中：

- `get_db_connection()` 会新建 psycopg2 连接。
- 普通 `_fetch()` / `_execute()` 已经不是每次查询都新建连接，而是通过 thread-local 复用连接。
- 需要原子事务的函数，如注册、入库、出库，仍然单独开连接、提交/回滚、关闭连接。

这说明“每次查询都新建/关闭连接”不是完全准确的当前现状。但当前实现仍有性能与稳定性问题：

- thread-local 复用不是标准连接池，没有连接数量上限、统一回收、健康检查和关闭生命周期。
- 远程测试库网络 RTT 会放大多次 SQL 往返。
- 前端首屏一次加载多个 API：
  - Seller 工作台：`summary + stock + movements`。
  - 通用空间页：`overview + resources + persons + transactions + timeline`。
- 单个接口内部也会执行多条 SQL，例如 `/seller/summary` 会执行多次聚合查询。

### 1.2 PM 结论

本轮需要做 **连接池 + 首屏聚合加载**，只做连接池不够。

目标不是追求完美性能架构，而是让录屏和 MVP 使用体验明显改善：

- 切换空间后首屏更快出现。
- 页面不因多个 API 与多次 SQL 往返产生明显等待。
- 连接生命周期可控，不因线程或测试残留产生连接泄漏。

## 2. 产品目标

P0 目标：

1. 登录、切换空间、Seller 工作台、通用空间观察页加载更快。
2. 页面切换后不出现长期空白或卡在 loading。
3. 保持所有 API 业务响应不变，已有页面不破。
4. 继续坚持：
   - 不暴露 DB 数字 ID。
   - 不恢复 `pid/oid`。
   - 默认测试不触发真 LLM。
   - 不写真实密钥。

体验验收目标：

| 场景 | 目标 |
| :--- | :--- |
| 登录后 personal 首屏 | 1.5s 内出现主内容 |
| 切换到 ecommerce 工作台 | 1.5s 内出现指标和库存 |
| 切换到 campaign 空间观察页 | 2.0s 内出现概览和时间线 |
| Seller AI | 本轮不优化 LLM 推理耗时，只保证上下文数据查询不拖慢 |

## 3. 范围

### 3.1 P0 必做

后端：

1. 用 `psycopg2.pool.ThreadedConnectionPool` 替换当前 thread-local 连接复用。
2. 增加 DB pool 配置：
   - `DB_POOL_MIN`
   - `DB_POOL_MAX`
   - 推荐默认：`1 / 10`
3. `_fetch()` / `_execute()` 从 pool 取连接，用完归还。
4. 原子事务函数从 pool 取连接，事务结束后归还。
5. FastAPI shutdown 时关闭连接池。
6. 新增首屏聚合接口：
   - `GET /seller/workbench`
   - `GET /spaces/current/dashboard`

前端：

1. Seller 工作台优先调用 `/seller/workbench`。
2. 通用空间页优先调用 `/spaces/current/dashboard`。
3. 保留页面现有展示结构，不做视觉重构。
4. loading 状态必须在聚合请求成功/失败后正确结束。

测试：

1. 补连接池单元/集成测试。
2. 补聚合接口契约测试。
3. 补前端 API client 与页面加载测试。
4. 补 Demo 录屏 smoke 性能门禁。

### 3.2 P1 可做

- 给 SQL 打轻量耗时日志，慢查询超过 300ms 打 warning。
- 合并 `/seller/summary` 内部 SQL，减少多次 `_fetch()`。
- 通用空间页拆分首屏和次屏，首屏先展示 overview/timeline，资源明细延迟加载。

### 3.3 不做事项

- 不引入 SQLAlchemy。
- 不切换到 asyncpg。
- 不改数据库表结构。
- 不改认证/JWT 结构。
- 不改业务字段命名。
- 不为了性能缓存跨组织数据。
- 不引入 Redis 或外部缓存。

## 4. 后端设计

### 4.1 配置

修改 `src/config.py`：

`profile.yaml` 允许新增非机密配置：

```yaml
database:
  pool_min: 1
  pool_max: 10
```

环境变量覆盖：

```bash
DB_POOL_MIN=1
DB_POOL_MAX=10
```

约束：

- `pool_min >= 1`
- `pool_max >= pool_min`
- `pool_max <= 50`
- 配置错误启动即失败，不允许静默降级。
- `password` 仍只能来自环境变量或 `.env`，不得写进 `profile.yaml`。

### 4.2 连接池模块

在 `src/db/database.py` 中实现：

```python
from psycopg2.pool import ThreadedConnectionPool

_pool = None
_pool_lock = threading.Lock()

def init_connection_pool() -> None: ...
def close_connection_pool() -> None: ...
def get_pooled_connection(): ...
def release_pooled_connection(conn, *, close: bool = False) -> None: ...
```

要求：

- pool 懒加载或 startup 初始化均可，但必须线程安全。
- 连接创建时继续设置 `options="-c timezone=Asia/Shanghai"`。
- `_fetch/_execute` 使用 autocommit 连接，保持原先“每条语句独立提交”的语义。
- 出现 `OperationalError` / `InterfaceError` 时，丢弃坏连接并重试一次。
- 出现 `PoolError` / pool exhausted 时必须返回受控错误，不允许用户看到未包装 500。
  - DB helper 可抛出自定义 `DatabasePoolExhaustedError`。
  - FastAPI 层必须转成 503，或注册全局 exception handler 转成 503。
  - 测试必须覆盖 `pool_max` 耗尽场景。
- 普通业务异常时 rollback 后归还连接。
- cursor 必须用 context manager 或 finally 关闭，不能依赖连接归还时隐式清理。
- `close_connection_pool()` 可重复调用，不能抛未捕获异常。

### 4.3 普通查询 helper

`_fetch(sql, params)`：

- 从连接池取连接。
- `cursor_factory=RealDictCursor`。
- 返回 `List[Dict[str, Any]]`。
- finally 中归还连接。

`_execute(sql, params, fetch_returning)`：

- 从连接池取连接。
- autocommit 模式下执行。
- `fetch_returning=True` 时返回 rows。
- 否则返回 rowcount。
- finally 中归还连接。

### 4.4 原子事务函数

以下函数不得继续直接 `conn.close()`：

- `register_personal_space`
- `init_database`
- `create_space` 相关 DB helper，如已有事务 helper
- `execute_purchase_in`
- `execute_sales_out`
- `delete_campaign_import`
- 其他手写 `conn = get_db_connection()` 的事务函数

要求：

- 从连接池取连接。
- 事务开始前 `conn.autocommit = False`。
- 成功 `commit()`。
- 异常 `rollback()`。
- finally 中恢复连接状态并归还连接。
- 对需要独占事务的逻辑，不允许拆成多个 `_execute()`。

注意：

- `init_database(drop_all=True)` 可能在测试中执行。执行前应关闭旧 pool 或确保获取新连接后不被旧连接阻塞。
- Demo Destroy & Rebuild 前仍必须停止后端服务，避免应用连接占住目标数据库。

### 4.5 FastAPI 生命周期

修改 `src/app.py`：

- startup：
  - `init_connection_pool()`
  - `init_database(drop_all=False)`
  - `ensure_default_super()`
- shutdown：
  - `close_connection_pool()`

验收：

- 启动日志能看到 pool 初始化。
- 关闭服务后测试库 `pg_stat_activity` 不残留应用连接。

## 5. 聚合接口设计

### 5.1 `GET /seller/workbench`

用途：Seller 工作台首屏一次拿到 summary、stock、movements，减少前端 3 个并发 API。

认证：

- 必须 `require_ecommerce_context`。
- 拒绝身份 query 参数：
  - `id`
  - `puid`
  - `ouid`
  - `person_id`
  - `organization_id`
  - `resource_id`
  - `warehouse_id`

Query：

| 参数 | 类型 | 默认 | 约束 |
| :--- | :--- | :--- | :--- |
| movements_limit | int | 10 | 1..50 |
| low_stock_threshold | float | 5 | >= 0 |
| top_n | int | 5 | 1..20 |

响应：

```json
{
  "status": "ok",
  "summary": { "...": "same as /seller/summary" },
  "stock": [{ "...": "same as /seller/stock" }],
  "movements": [{ "...": "same as /seller/inventory-movements" }]
}
```

红线：

- 不返回 DB 数字 ID。
- 不返回 `pid/oid`。
- 非 ecommerce 空间返回 403。
- 不触发 LLM。

### 5.2 `GET /spaces/current/dashboard`

用途：通用空间观察页一次拿到 overview、resources、persons、transactions、timeline，减少 5 个 API。

认证：

- 必须 `require_strict_org_context`。
- 拒绝身份 query 参数。

Query：

| 参数 | 类型 | 默认 | 约束 |
| :--- | :--- | :--- | :--- |
| transaction_limit | int | 20 | 1..100 |

响应：

```json
{
  "status": "ok",
  "overview": { "...": "same as /spaces/current/overview" },
  "resources": { "...": "same as /spaces/current/resources" },
  "persons": [{ "...": "same as /spaces/current/persons" }],
  "transactions": [{ "...": "same as /spaces/current/transactions" }],
  "timeline": { "events": [{ "...": "same as /spaces/current/timeline" }] }
}
```

红线：

- 不返回 DB 数字 ID。
- 不返回 `pid/oid`。
- 不调用 `/seller/*`。
- ecommerce 空间也可调用该接口，但前端 ecommerce 首屏应优先使用 `/seller/workbench`。

## 10. 风险与处理

| 风险 | 影响 | 处理 |
| :--- | :--- | :--- |
| pool 连接泄漏 | DB 连接耗尽 | 所有 getconn 必须 finally putconn；补 pg_stat_activity 验收 |
| 事务连接被 autocommit 污染 | 原子性失效 | 事务 helper 明确设置 autocommit=False，归还前恢复 |
| 聚合接口泄漏 DB ID | 安全红线 | DTO 显式映射 + 递归扫描测试 |
| 聚合接口导致大响应 | 首屏仍慢 | limit 参数约束，timeline/transactions 限量 |
| Demo Destroy & Rebuild 被连接占用 | DROP DATABASE 失败 | 录屏前仍先停后端；shutdown 关闭 pool |
