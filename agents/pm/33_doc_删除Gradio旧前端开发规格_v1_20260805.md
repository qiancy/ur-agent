# FE-11 删除 Gradio 旧前端开发规格

> 角色：产品经理 / 项目经理
> 日期：2026-08-05
> 优先级：P1，比赛交付前建议完成
> 目标：删除旧 Gradio 前端，统一产品入口为 `web/` Vue + Vite 前端，降低双前端维护成本与交付误用风险。

## 1. 背景

项目早期使用 `src/frontend.py` 提供 Gradio UI。当前产品前端已经迁移到 `web/`：

- Vue + Vite + TypeScript 已实现登录、Header 空间切换、Seller 工作台、库存、流水、摘要、Seller AI、通用空间观察、空间治理页面。
- Playwright 录屏脚本与 Vue 单元测试均围绕 `web/` 前端。
- 后端 `src/app.py` 已作为 FastAPI API 服务入口。

继续保留 Gradio 会产生问题：

- 用户、开发团队和录屏脚本可能误启动旧入口。
- `src/frontend.py` 继续携带旧 UI 逻辑，增加 DB ID / 旧字段扫描噪音。
- `requirements.txt` 继续安装 `gradio`，增加依赖体积与安全扫描面。
- 文档同时存在 `7860 Gradio` 和 `5173 Vue` 两套运行方式，交付口径不统一。

PM 结论：FE-11 应执行 **硬退役 Gradio 前端**，不保留双前端兼容。

## 2. 产品目标

1. 产品唯一前端入口为 `web/` Vue 前端。
2. 后端只负责 FastAPI API，不再承载 Gradio UI。
3. 启动脚本、README、架构文档、测试计划全部指向新前端。
4. 默认依赖不再安装 Gradio。
5. 保持现有后端 API、Vue 前端行为、Demo 录屏流程不变。

## 3. 范围

### 3.1 必做

删除/修改：

| 类型 | 路径 | 操作 |
| :--- | :--- | :--- |
| 旧前端源码 | `src/frontend.py` | 删除 |
| 旧前端测试 | `agents/tdd/test_frontend_render.py` | 删除或改为历史归档文档，不再纳入 pytest |
| Python 依赖 | `requirements.txt` | 删除 `gradio` |
| 启动脚本 | `scripts/unires_agent.sh` | 删除 Gradio 启动逻辑，改为 Vue 前端启动/提示 |
| README | `README.md` | 删除 `python src/frontend.py`，改为 `cd web && npm run dev/build/preview` |
| 架构文档 | `docs/ARCHITECTURE.md` | 删除 Gradio UI 层描述，改为 Vue/Vite 前端 |
| PM/TDD 文档 | 相关 BE-04/BE-05 历史文档 | 不强制改历史记录，但新增说明“Gradio 已退役” |

保留：

| 路径 | 说明 |
| :--- | :--- |
| `web/` | 唯一产品前端 |
| `src/app.py` | FastAPI 后端入口 |
| `src/routers/*` | API 路由 |
| `agents/tdd/playwright/*` | Vue E2E 录屏测试 |

### 3.2 不做

- 不重构 Vue 前端视觉。
- 不改后端业务 API。
- 不改 JWT / puid / ouid 规则。
- 不引入 Nginx 或生产部署系统。
- 不把 Vue 静态文件挂载到 FastAPI，除非 PM 单独安排部署任务。
- 不为了旧 Gradio 提供兼容入口。

## 4. 目标运行方式

开发/录屏环境：

```bash
# 后端
PYTHONPATH=. python -m uvicorn src.app:app --host 0.0.0.0 --port 8000

# 前端开发模式
cd web
npm run dev -- --host 0.0.0.0 --port 5173
```

比赛演示稳定模式：

```bash
# 后端
PYTHONPATH=. python -m uvicorn src.app:app --host 0.0.0.0 --port 8000

# 前端预览模式
cd web
npm run build
npm run preview -- --host 0.0.0.0 --port 5173
```

访问地址：

```text
http://localhost:5173
```

## 5. 启动脚本规格

修改 `scripts/unires_agent.sh`：

1. 删除对 `src/frontend.py` 的进程检测、启动、日志路径和端口 7860 说明。
2. 前端命令改为 `web/`：
   - dev 模式：`npm run dev -- --host 0.0.0.0 --port 5173`
   - preview 模式：`npm run build` 后 `npm run preview -- --host 0.0.0.0 --port 5173`
3. 如果脚本当前只适合 Python 服务，也可以先不自动启动前端，但必须输出明确提示：

```text
Frontend: cd web && npm run dev -- --host 0.0.0.0 --port 5173
```

4. 启动脚本不得再出现：

```text
src/frontend.py
gradio
7860
```

除非是在历史说明或迁移注释中，且不影响实际执行。

## 6. 测试调整

### 6.1 删除旧测试

`agents/tdd/test_frontend_render.py` 直接 import `src.frontend`，删除 `src/frontend.py` 后必然失败。

处理方式：

- 首选：删除该测试文件。
- 若需要保留历史，则改名到文档目录，例如：

```text
agents/tdd/archive/test_frontend_render_gradio_legacy.py.disabled
```

该文件不得被 pytest 默认收集。

### 6.2 保留/强化 Vue 测试

必须继续通过：

```bash
cd web
npm run test
npm run build
```

必须继续通过核心后端测试：

```bash
python3 -m compileall src agents/tdd
python3 -m pytest agents/tdd/test_auth_api.py agents/tdd/test_spaces_api.py -v
python3 -m pytest agents/tdd/test_demo_smoke.py agents/tdd/test_recording_smoke.py -v
```

如测试数据库不可用，开发团队必须说明未运行原因，并至少保证无 DB 的配置/PERF/Vue 测试全绿。

## 7. 安全与红线

删除旧前端后必须扫描：

```bash
rg -n "gradio|src/frontend.py|python src/frontend.py|7860" README.md docs agents scripts src requirements.txt
rg -n '"pid"|"oid"|\bpid\b|\boid\b' src web/src agents/tdd/playwright
rg -n 'person_id|organization_id|membership_id|account_id|resource_id|warehouse_id|transaction_id' web/src
rg -n 'sk-|AKIA|api[_-]?key|secret|password|token' web/src src --type py --type ts
```

验收口径：

- `gradio` 在源码和依赖中零命中。
- `src/frontend.py` 在运行文档和脚本中零命中。
- `7860` 不再作为产品前端端口出现。
- Vue 前端不暴露 DB 数字 ID。
- 旧 `pid/oid` 不作为业务字段恢复。
- 不新增真实密钥。

历史 PM/TDD 文档如必须保留旧记录，可不强制清零，但需要新增说明：

```text
Gradio frontend 已在 FE-11 退役，当前产品前端以 web/ Vue 为准。
```

## 9. 开发步骤

建议开发团队按以下顺序执行：

1. TDD 红灯：
   - 先运行 `python3 -m pytest agents/tdd/test_frontend_render.py -v` 确认该测试依赖旧 Gradio。
   - 决定删除或归档该测试。
2. 删除 `src/frontend.py`。
3. 删除 `requirements.txt` 中的 `gradio`。
4. 修改 `scripts/unires_agent.sh`。
5. 修改 `README.md` 与 `docs/ARCHITECTURE.md`。
6. 更新 `agents/pm/4-进度跟踪.md`。
7. 运行验证命令。
8. 执行安全扫描。
9. PM review 后提交。

## 10. 验收标准

必须全部满足：

1. `src/frontend.py` 不存在。
2. `requirements.txt` 不含 `gradio`。
3. 启动脚本不再启动 Gradio。
4. README 和架构文档只描述 Vue/Vite 前端。
5. `cd web && npm run test && npm run build` 通过。
6. `python3 -m compileall src agents/tdd` 通过。
7. 默认 pytest 不再收集任何依赖 `src.frontend` 的测试。
8. Playwright 录屏脚本仍以 `localhost:5173` 为前端入口。
9. 安全扫描无新增密钥、无旧身份字段恢复、无 DB ID 对外展示。

## 11. 回滚策略

如 FE-11 导致 Demo 前端无法启动：

1. 不恢复 Gradio。
2. 优先修复 `web/` 启动脚本或环境依赖。
3. 临时手动启动：

```bash
PYTHONPATH=. python -m uvicorn src.app:app --host 0.0.0.0 --port 8000
cd web && npm run dev -- --host 0.0.0.0 --port 5173
```

只有在 PM 明确批准时，才允许从 Git 历史临时恢复 `src/frontend.py` 作为调试工具；不得作为产品入口提交。

## 12. PM 结论

FE-11 可安排开发团队执行。

删除 Gradio 是产品收口动作，不是视觉优化。它的核心价值是让比赛交付、开发运行、测试脚本和文档都指向同一个产品前端，避免双入口造成演示事故。
