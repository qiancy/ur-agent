## 2. 目标仓库形态

目标 GitHub 工作区已由用户确认：

```text
/data/research/amd.com/ur-agent
```

本次 GitHub 交付仓必须完成清晰的 `backend/` + `frontend/` 代码结构。仓库关系如下：

- `unires-agent`：开发工作仓，保留 `agents/`、PM/SA/TDD 过程资产和历史文档。
- `ur-agent`：比赛/开源交付仓，只保留产品源码、运行脚本、必要用户文档和可运行测试，并以 `backend/`、`frontend/` 作为第一层工程边界。
- 测试在 `ur-agent` 通过后，再提交/推送 GitHub；不要把清理动作反向污染 `unires-agent`。

```text
ur-agent/
├── backend/
│   ├── src/                # FastAPI backend source
│   ├── scripts/            # DB init, seed, service helpers
│   ├── data/               # seed/init data, no secrets
│   ├── requirements.txt
│   ├── profile.yaml        # non-secret config only
│   ├── .env.example        # placeholders only
│   └── Dockerfile
├── frontend/               # Vue + Vite frontend, source from web/
├── tests/
│   ├── backend/            # API/unit smoke tests, source from agents/tdd/*.py
│   └── playwright/         # E2E recording tests
├── docs/                   # 面向评委/用户的 API、架构、Demo 文档
├── README.md
├── pytest.ini
├── docker-compose.yml
└── LICENSE
```

说明：

- `web/ -> frontend/`、`src/ -> backend/src/`、`scripts/ -> backend/scripts/` 是本次 GH-01 的核心目标，不再推迟到赛后。
- 后端从 `backend/` 目录启动，命令为 `cd backend && PYTHONPATH=. python -m uvicorn src.app:app --host 0.0.0.0 --port 8000`。
- 前端从 `frontend/` 目录启动，命令为 `cd frontend && npm run dev -- --host 0.0.0.0 --port 5173`。
- 后端配置文件放在 `backend/profile.yaml`，真实机密放在 `backend/.env`，只提交 `backend/.env.example`。
- `agents/` 是开发协作与过程资产，整体不复制到 GitHub 干净仓库。
- 可复现测试从 `agents/tdd/` 白名单复制到 `tests/backend/` 和 `tests/playwright/`，避免目标仓库出现 `agents/`。
- `docker-compose.yml` 必须改为从 `./backend` 构建后端，不得继续假设根目录存在 `src/`。

## 3. 复制策略：白名单优先

PM 决策：采用 **白名单复制**，不是整仓排除式复制。

原因：

- 干净 GitHub 仓库应呈现产品代码，而不是开发过程档案。
- 白名单能避免 `.env`、过程文档、临时输出、历史报告误入仓库。
- 评委只需要看到可运行代码、必要文档、可复现测试。
