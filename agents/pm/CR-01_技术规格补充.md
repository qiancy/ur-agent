## 1. 数据模型基线（已核实现状）

- 商品 = `resource` 表 `type='physical'` 的行：`name`=product_uid，`status`=active/inactive，`unit` 已有列；`content` 列为描述载体（物理商品当前未用，可安全复用）。
- **PM 决策（P0-1）**：参赛版**取消独立商品 `name` 字段**——`product_uid` 直接作为商品业务名/编号（无存储位置，不加列迁移）；`description` 复用 `resource.content`。
- 库存数量来自 `resource_warehouse.quantity` 汇总；**库位数 = 该商品 `resource_warehouse` 的 `location_path` 去重数**，字段名统一为 `stock_location_count`（与既有 Seller summary 口径一致，**不用** `warehouse_count`）。
- 上下文获取：`src/routers/deps.py::require_org_context(request)`（ecommerce 用 `require_ecommerce_context`），禁止接受 `puid/ouid` 等身份查询参数（沿用 `_reject_identity_params`）。
- 空间包导入沿用 `POST /campaigns/import` + `data/campaigns/*.json`，`campaign_import` 表记录；不新增 workspace 表。

## 2. 后端 API 契约

### 2.1 BE-09 Seller 商品 API（`src/routers/seller.py` 扩展）

#### GET /seller/products

- 认证：`require_ecommerce_context`（JWT，非 ecommerce 403）。
- 响应 200：

```json
[
  {
    "product_uid": "SKU-001",
    "unit": "个",
    "status": "active",
    "stock_total": 120,
    "stock_location_count": 2,
    "description": "可选描述（来自 resource.content）"
  }
]
```

- 店铺隔离：仅当前 JWT 组织。
- 默认返回 active + inactive 都列出（status 字段区分）。
- **无独立 `name` 字段**：`product_uid` 即商品名/编号（PM P0-1 决策）。

#### POST /seller/products

- 请求体（业务字段，无 DB ID）：

```json
{
  "product_uid": "SKU-002",
  "unit": "个",
  "description": "可选描述"
}
```

- 201：返回同 2.1 列表项结构（status=active，stock_total=0，stock_location_count=0）。
- 409：同组织重复 `product_uid`。
- 422：缺 `product_uid`/`unit`（**无 name 字段**）。

#### PATCH /seller/products/{product_uid}

- 请求体：`{ "status": "inactive" }` 或 `"active"`。
- 200：返回 `{product_uid, unit, status}`。
- 404：组织内不存在该 `product_uid`。
- 不删除任何历史流水（`inventory_movement`、`resource_warehouse` 保留）。

### 2.2 BE-10 空间观察只读 API（新文件 `src/routers/spaces.py`）

全部走 `require_strict_org_context`（**仅 JWT，不接受任何 `ouid`/`puid` 查询参数**；不能复用 `require_org_context`，因其含公开 `?ouid=` 兜底路径），仅 GET。

> 设计依据：现有 `GET /resource` 内部执行 `SELECT r.*`，会返回 `id`/`organization_id`/`person_id`/`embedding` 等 DB 字段，违反「业务界面禁 DB ID」红线，因此**不直接复用**，由 `/spaces/current/*` 提供只含业务字段的清洗 DTO。

#### GET /spaces/current/overview

响应 200：

```json
{
  "space": {
    "ouid": "zhangsan_family",
    "name": "张三家庭",
    "type": "family",
    "role": "owner"
  },
  "counts": {
    "resources": 6,
    "persons": 4,
    "transactions": 3,
    "recent_events": 2
  },
  "funds": 8500.0
}
```

- `recent_events`：若当前组织有 campaign_import，为事件数；否则 0。
- `persons`：该组织 membership 人数。

#### GET /spaces/current/resources

响应 200（按 `type` 分组，仅业务字段，无 `id`/`person_id`/`embedding`）：

```json
{
  "grouped": {
    "physical": [
      {
        "name": "教材",
        "type": "physical",
        "unit": "本",
        "amount": 12,
        "description": "小学五年级数学",
        "locations": [
          { "warehouse_code": "WH1", "location_path": "A1", "quantity": 12, "unit": "本" }
        ]
      }
    ],
    "knowledge": [
      { "name": "错题本", "type": "knowledge", "unit": "份", "amount": null, "description": "张小宝错题整理" }
    ],
    "financial": [],
    "human": []
  }
}
```

- **physical 资源必须带 `locations` 数组**（P1-3 PM 决策）：`warehouse_code`/`location_path`/`quantity`/`unit`，无 DB ID；仅当该资源在 `resource_warehouse` 有库存时非空。
- `amount`：physical 为该空间全部 `locations.quantity` 之和（跨库位汇总）；**非 physical 的 `amount` 取 `resource.amount`，无值则 null；`description` 取 `resource.content`**（当前系统为 resource 单表，`virtual_assets` 仅是旧表清理遗留名，不引用，P2 澄清）。

#### GET /spaces/current/persons

响应 200：

```json
[
  { "name": "张三", "puid": "zhangsan", "role": "owner" }
]
```

#### GET /spaces/current/transactions（新增，P0-2 PM 决策）

- 资金流**必须走 strict JWT 的 spaces namespace**，前端非 ecommerce **不得**调用旧 `/summary`、`/transactions`（二者走 `require_org_context`，含公开 `?ouid=` 兜底路径）。
- 响应 200（清洗 DTO，仅业务字段，无 DB ID）：

```json
[
  {
    "transaction_uid": "txn-0001",
    "from_party_name": "张三",
    "to_party_name": "书店",
    "amount": 128.0,
    "category": "教育支出",
    "description": "购买教材",
    "created_at": "2026-08-01T10:00:00"
  }
]
```

- 按 `created_at` 倒序，limit 默认 20（可传 `?limit=`，校验 1–100）。
- 资金汇总仍由 `/spaces/current/overview` 的 `funds` 提供，本接口只给明细。

#### GET /spaces/current/timeline

响应 200：

```json
{
  "events": [
    {
      "seq": 1,
      "campaign_code": "family_learning",
      "campaign_name": "家庭学习空间",
      "title": "每日学习要求",
      "description": "完成数学口算 20 题",
      "payload": {
        "info_flow": "通知下发",
        "logistics_flow": "",
        "people_flow": "张小宝",
        "risk": ""
      }
    }
  ]
}
```

- **多导入场景（P1-2 PM 决策，已冻结）**：返回当前 JWT 组织关联的**所有 active import** 的事件，排序 = `campaign_code ASC, seq ASC`；事件带 `campaign_code`/`campaign_name` 业务字段。
- 当前组织无任何 campaign_import（或无事件）时返回 `{ "events": [] }`。
- 复用 `get_campaign_replay`/campaign_import 查询，按 JWT 组织过滤。
- `payload` 即事件导入时的完整配置（含维度标签顶层字段）。

#### 观察面板数据来源（T3）

| 面板数据 | 接口 | 说明 |
| :--- | :--- | :--- |
| 空间概览/计数/funds | `GET /spaces/current/overview` | 清洗 DTO，无 DB ID |
| 资源分组（含 locations） | `GET /spaces/current/resources` | 清洗 DTO，按 type 分组 |
| 人员 | `GET /spaces/current/persons` | 清洗 DTO |
| 资金流明细 | `GET /spaces/current/transactions` | **新增，strict JWT** |
| 时间线 | `GET /spaces/current/timeline` | 清洗 DTO，多导入排序 |

> **P0-2**：非 ecommerce 面板全部资金数据只走 `/spaces/current/*`；**禁止**复用旧 `/summary`、`/transactions`（`require_org_context` 含公开 `?ouid=` 兜底）。

## 3. 前端规格（FE-09）

### 3.1 AppHeader 收口（`web/src/components/AppHeader.vue`，T2）

- 保留：用户 `personName`、`puid`、组织名、`ouid`、类型 chip、角色、组织切换下拉、退出登录。
- 移除：AI 输入框、`问 AI` 按钮（及 `@ask` emit、`aiEnabled` 逻辑）。
- 新增：
  - `AI` 入口（小链接/按钮）：点击 emit `navigate-ai`；App 中 ecommerce → `currentView='chat'`；非 ecommerce → `currentView='placeholder'`（占位文案「该业务空间暂未接入 AI」）。
  - `空间` 菜单（`SpaceMenu.vue` 或 Header 内下拉）：管理空间 / 加入空间 / 审核申请 / 退出空间。`owner/admin` 才显示「审核申请」；普通成员显示「加入空间」「退出空间」。全部进入 `PlaceholderView.vue`（明示「功能即将开放」占位）。

### 3.2 Sidebar 动态导航（`web/src/components/SidebarNav.vue`，T2）

props 新增 `orgType: string`。按 `orgType === 'ecommerce'` 切换两组导航键：

- ecommerce：工作台(workbench) / 商品(products) / 库存(stock) / 库存流水(movements) / 经营摘要(summary) / Seller AI(chat)
- 非 ecommerce：空间总览(overview) / 资源(resources) / 人员(persons) / 时间线(timeline) / 多维观察(flows)

### 3.3 App.vue 接线（T2 独占）

- `currentView` 路由键按 `orgType` 决定可用集合；`currentComponent` 映射：

| 键 | 组件 | 归属 |
| :--- | :--- | :--- |
| workbench/stock/movements/summary/chat | 现有视图 | FE-07 已有 |
| products | `ProductsView` | T3 |
| overview/resources/persons/timeline/flows | `GenericSpaceView`（内部 tab 或单页） | T3 |
| placeholder | `PlaceholderView` | T2 |

- 非 ecommerce 时不再渲染「暂未接入」空状态，改渲染 `GenericSpaceView`；ecommerce 渲染 Seller 视图。
- 保持：切换组织重新签发 JWT（已有）、Header 事件、401 统一清 token 回登录。

### 3.4 ProductsView（T3）

- 列表列：`product_uid`（即商品名/编号）、单位、状态、库存总数、库位数(`stock_location_count`)、描述（可选列）。
- 新增商品表单：`product_uid`（即名称）、单位、描述(可选)。**无独立名称字段**（P0-1）。
- 停用按钮（inactive 后可重新启用）；停用确认提示「历史流水保留」。
- 调用 `web/src/api/products.ts`（GET/POST/PATCH，Bearer token，401 抛 `logged-out`）。
- 入库/出库弹窗（`EntryFormModal.vue`）：product_uid 输入改为可搜索选择（active 商品），选择器无匹配时允许手动输入但必须二次确认「该商品不存在，确认新增？」。

### 3.5 GenericSpaceView（T3）

单页分五个区块（MVP 不做拓扑图）：

1. 空间概览：名称、类型、角色、资源数、人员数、交易数、最近事件数、funds（`/spaces/current/overview`）。
2. 资源观察：按 physical/knowledge/financial/human 分组，显示名称、类型、数量/金额、单位、说明；physical 展开库位明细（`locations`）。
3. 人员观察：成员名、puid、角色。
4. 时间线：`/spaces/current/timeline` 事件序列；空则显示空状态。
5. 多维流向：四分组面板（信息流=knowledge 资源+事件说明；物流=physical 资源+库位；人流=membership+事件参与方；资金流=`/spaces/current/transactions` 明细 + overview funds）。

数据源：`web/src/api/spaces.ts`（overview/resources/persons/transactions/timeline），全部 strict JWT。**非 ecommerce 空间禁止调用 `/seller/*`，也禁止复用旧 `/summary`、`/transactions`（P0-2）。**

## 5. 安全与回归（T5，QA-01）

### 5.1 命令

```bash
git diff --check
rg -n '"pid"|"oid"|\bpid\b|\boid\b' src web/src agents/tdd docs/API.md agents/pm
rg -n 'person_id|organization_id|membership_id|resource_id|warehouse_id|transaction_id|campaign_import_id' web/src
rg -n 'sk-[A-Za-z0-9]|AKIA[0-9A-Z]{16}|api[_-]?key|secret|password|token' web/dist
python3 -m compileall src agents/tdd
python3 -m pytest agents/tdd -q
cd web && npm test && npm run build
```

允许：测试中的禁止字段断言、登录密码字段。不允许：真实密钥、旧身份字段、业务界面 DB ID。

### 5.2 红线复核（对齐 CR-01 §8）

1. Header 无法切换多空间 → 禁上。
2. Seller 缺商品管理 → 禁上。
3. 非 ecommerce 仍显示「暂未接入」→ 禁上。
4. 切非 ecommerce 后仍调 `/seller/*` → 禁上。
5. 业务端出现 DB ID / `pid`/`oid` → 禁上。
6. 前端或文档提交真实密钥 → 禁上。
7. 默认测试触发真 LLM → 禁上。
8. 生产无预置示例空间数据 → 禁上。
