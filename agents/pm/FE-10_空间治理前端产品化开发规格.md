# FE-10 开发规格：空间治理前端产品化收尾

> 日期：2026-08-04
> 角色：PM / 产品负责人
> 状态：下发开发团队，比赛交付前 P0
> 背景：ORG-01 已完成 Header 收口和后端治理能力，但当前 Header「空间」菜单进入主区后仍显示「敬请期待」，商业系统观感不可接受。本规格替代 CR-01/FE-09 中“空间治理项可占位”的旧约定。

---

## 1. 目标

把 Header 的空间治理入口做成可用的产品级功能，而不是占位页。

用户登录后应能清楚完成以下事情：

1. 看见自己是谁、在哪个组织/业务空间、当前角色是什么。
2. 在已加入的空间之间切换，且切换必须由后端校验 membership 后重新签发 JWT。
3. 创建新的业务空间。
4. 查看当前空间成员，并根据权限邀请、移除、转让 owner。
5. 接受别人邀请，或申请加入别人的空间。
6. owner/admin 审核加入申请。
7. 普通成员退出非 personal 空间。

本阶段不做独立 `workspace` 表。系统模型继续固定为：

```text
account -> person -> membership -> organization(workspace)
```

`organization` 在当前 MVP 中就是业务空间的数据边界。

---

## 2. 产品原则

1. Header 只承担全局上下文和治理入口，不承载具体业务操作和 AI 对话。
2. Sidebar 是当前业务空间内部导航；Seller AI 保留在 Sidebar / 业务主区。
3. Main View 必须渲染真实页面。禁止继续把「管理空间」「加入空间」「审核申请」「退出空间」接到 `PlaceholderView`。
4. 所有空间治理操作必须走后端 API，不能前端假操作。
5. 所有 API、前端状态、表格列、日志和测试快照不得暴露 DB 数字 ID。
6. 继续使用 `puid/ouid` 字符串业务身份；禁止恢复 `pid/oid`。
7. personal 空间是注册默认空间：不可退出、不可邀请成员、不可被踢出，不能由用户手工创建。

---

## 3. 全局布局

目标结构：

```text
┌─────────────────────────────────────────────────────────────┐
│ AppHeader                                                    │
│ [Logo] 当前空间 | 用户信息 | 空间切换 | 空间治理 | 退出       │
├─────────┬───────────────────────────────────────────────────┤
│ Sidebar │ Main View                                          │
│ 当前空间 │ 业务视图或空间治理视图                              │
│ 导航菜单 │                                                     │
└─────────┴───────────────────────────────────────────────────┘
```

### 3.1 AppHeader 必须显示

- 当前用户：`person.name` 和 `puid`，例如 `张三 (zhansan)`。
- 当前业务空间：组织名称、`ouid`、组织类型、当前角色，例如 `淘宝小店 A / zhansan_shop / ecommerce / owner`。
- 空间切换下拉：
  - 数据来自登录响应或 `GET /auth/me/organizations`。
  - 每项显示：组织名 + 类型 + 角色。
  - 切换只调用 `POST /auth/switch-organization`，请求体只允许 `{ "ouid": "target_ouid" }`。
  - 成功后更新 token、`unires_ctx`、Header、Sidebar、Main View。
- 空间治理入口：
  - `管理空间`
  - `创建空间`
  - `加入空间`
  - `审核申请`，仅 owner/admin 可见
  - `退出空间`，personal 空间不显示；owner/admin 也可显示但需受最后 owner 保护
- 退出登录：清除 JWT 和上下文，返回登录页。

### 3.2 AppHeader 禁止项

- 不允许恢复 Header AI button。
- 不允许 `data-test="header-ai-entry"`。
- 不允许 `navigate-ai` emit/listener。
- 不允许 Header 中直接发起 `/seller/chat` 或 `/chat`。

## 4. 组织切换流程

1. 用户点击 Header 的组织下拉。
2. 前端展示当前账号拥有 membership 的所有组织。
3. 用户选择目标组织。
4. 前端调用：

```http
POST /auth/switch-organization
Authorization: Bearer <old_token>

{ "ouid": "target_ouid" }
```

5. 后端校验当前 `puid` 对目标 `ouid` 有 membership。
6. 成功后返回新 JWT 和新的上下文 DTO。
7. 前端保存新 token，更新 `localStorage.unires_ctx`。
8. Main View 重置：
   - ecommerce：进入 `workbench`。
   - 非 ecommerce：进入 `overview`。
   - 空间治理视图打开时切换组织，自动关闭治理视图并回到目标空间默认页。
9. 失败时保留原 token 和原上下文，显示错误提示，不允许前端假切换。

## 5. Main View：空间治理页面

### 5.1 `SpaceManageView`：管理空间

入口：Header 空间菜单 `管理空间`。

页面必须包含：

- 空间资料区：
  - 组织名、`ouid`、类型、当前角色、描述。
  - `ouid` 可复制。
  - personal 空间显示固定说明：个人空间由注册自动创建，不支持邀请/退出/删除。
- 成员区：
  - 表格列：姓名、`puid`、角色、加入时间、操作。
  - 不显示 `id/person_id/organization_id/membership_id`。
  - owner/admin 可看到 `邀请成员` 按钮。
  - owner/admin 可对 member/viewer 执行移除。
  - owner 可对已有成员执行转让 owner。
  - 最后 owner、personal 空间、当前用户移除自己等受保护场景必须禁用按钮并显示原因。
- 邀请区：
  - 表单字段：受邀人 `puid`、角色(member/viewer)。
  - 提交后显示 `invite_uid`，提供复制按钮。
  - 失败显示后端错误。
- 空状态：
  - 无成员以外的空数据时显示「暂无其他成员」，不能显示「敬请期待」。

### 5.2 `SpaceCreateView` 或 `CreateSpaceModal`：创建空间

入口：Header 空间菜单 `创建空间`，也可在管理空间页右上角放同一个按钮。

字段：

- 空间名称 `name`，必填。
- 空间类型 `org_type`：`family/ecommerce/campaign/starship/company`。
- 业务空间标识 `ouid`，可选；填写时只允许英文、数字、下划线、连字符。
- 描述 `description`，可选。

提交：

```http
POST /spaces
```

成功：

- 后端返回新空间上下文和 JWT。
- 前端立即切换到新空间。
- 刷新 Header 组织列表。
- ecommerce 进入 `workbench`，非 ecommerce 进入 `overview`。

禁止：

- 用户选择 `personal` 类型。
- 请求中出现 DB ID 字段。

### 5.3 `JoinSpaceView`：加入空间

入口：Header 空间菜单 `加入空间`。

页面分两个 Tab：

1. 接受邀请
   - 输入 `invite_uid`。
   - 调用 `POST /spaces/invites/accept`。
   - 成功后提示已加入，并刷新 Header 组织列表。
   - 如后端返回目标 `ouid`，提供「切换过去」按钮，按钮必须调用 `/auth/switch-organization`。
2. 申请加入
   - 输入目标 `ouid`。
   - 可选申请说明 `message`。
   - 调用 `POST /spaces/{ouid}/join-requests`。
   - 成功显示 `request_uid` 和状态 `pending`。

同时显示：

- 我的待处理邀请列表。
- 我的加入申请列表。

如后端暂未提供列表接口，开发团队必须补齐 BE-GOV 接口，不能用占位页替代。

### 5.4 `ReviewRequestsView`：审核申请

入口：Header 空间菜单 `审核申请`，仅 owner/admin 可见。

页面必须包含：

- 当前空间待审核申请列表：
  - `request_uid`
  - 申请人姓名
  - 申请人 `puid`
  - 申请说明
  - 创建时间
  - 状态
- 操作：
  - 通过：调用审批 API，成功后刷新成员和申请列表。
  - 拒绝：MVP 可新增轻量拒绝 API；如来不及，页面仍必须明确显示「本版仅支持通过，拒绝请忽略该申请」，但不能显示「敬请期待」。
- 空状态：
  - 无待审核时显示「暂无待审核申请」。

非 owner/admin 直接访问该视图时：

- 前端显示无权限页面。
- 后端接口仍必须返回 403。

### 5.5 `LeaveSpacePanel`：退出空间

入口：Header 空间菜单 `退出空间`。

行为：

- personal 空间不显示入口。
- 非 personal 空间进入确认面板。
- 确认后调用 `POST /spaces/leave`。
- 成功后刷新组织列表，并切换到 personal 空间或列表中的第一个可用空间。
- 如果当前用户是最后 owner，显示后端 409 错误，并引导先转让 owner。

## 6. 后端轻量补齐

现有后端已有 `POST /spaces`、邀请、接受邀请、申请加入、审批、退出、踢人、转让 owner 等写接口，但缺少支撑商业前端的列表/清洗接口。开发团队必须补齐以下 P0 接口。

### 6.1 成员列表

```http
GET /spaces/current/members
```

规则：

- `require_strict_org_context`。
- 返回当前 JWT 空间成员。
- DTO 字段：`puid/name/role/joined_at`。
- 不返回 DB ID。

### 6.2 当前空间待审核申请

```http
GET /spaces/current/join-requests?status=pending
```

规则：

- 仅 owner/admin。
- DTO 字段：`request_uid/requester_puid/requester_name/message/status/created_at`。
- 不返回 DB ID。

### 6.3 我的邀请

```http
GET /spaces/invites/mine?status=pending
```

规则：

- 当前登录用户按 `puid` 查询。
- DTO 字段：`invite_uid/ouid/organization_name/organization_type/role/status/created_by_puid/created_at`。
- 不返回 DB ID。

### 6.4 我的加入申请

```http
GET /spaces/join-requests/mine?status=pending
```

规则：

- 当前登录用户按 `puid` 查询。
- DTO 字段：`request_uid/ouid/organization_name/organization_type/message/status/created_at`。
- 不返回 DB ID。

### 6.5 拒绝加入申请（P1，可与 P0 同做）

```http
POST /spaces/join-requests/reject

{ "request_uid": "req_xxxxxxxx" }
```

规则：

- 仅目标空间 owner/admin。
- 将状态改为 `rejected`。
- 响应：`request_uid/ouid/status`。
- 不返回 DB ID。

### 6.6 可选：更新空间资料（P1）

```http
PATCH /spaces/current

{ "name": "张三家庭", "description": "..." }
```

规则：

- 仅 owner/admin。
- 不允许修改 `ouid` 和 `type`。
- personal 空间只允许修改名称和描述，不允许成员治理。

## 8. 交互与视觉要求

1. 使用当前 Style A 工作台风格，不重新换主题。
2. 空间治理页应是密集但清晰的后台界面，不做营销页。

## 12. 合并红线

出现任一情况不得合并：

1. Header 空间菜单仍进入 `PlaceholderView`。
2. 页面出现「敬请期待」「暂未开放」「TODO」作为空间治理主流程。
3. 空间切换没有调用 `/auth/switch-organization`，或前端假切换。
4. 接口/前端暴露 DB 数字 ID。
5. 恢复 `pid/oid`。
6. personal 空间可退出、邀请、踢人。
7. owner/admin 权限只在前端判断，后端没有 403。
8. 默认测试触发真 LLM。
