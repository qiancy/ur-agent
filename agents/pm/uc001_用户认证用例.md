# 用户认证用例

> 角色：项目经理  
> 状态：待开发实现  
> 范围：用户注册、用户登录  
> 约束：`person` 保存业务身份，`account` 保存登录凭据，`membership` 负责组织授权。

---

## 1. 数据模型约定

### person

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | integer | 数字主键 |
| `pid` | varchar | 用户英文标识，唯一，非特殊字符，例如 `caocao` |
| `name` | varchar | 展示名，例如 `曹操` |


### account

新增认证凭据表：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | integer | 数字主键 |
| `person_id` | integer | 外键，指向 `person.id` |
| `login` | varchar | 完整登录名，唯一，例如 `caocao@wei.cn` |
| `password` | text | 密码哈希，禁止明文存储 |
| `salt` | text | 密码盐；如使用 Argon2 内置 encoded hash，可为空 |
| `status` | varchar | 账号状态，默认 `active` |
| `created_at` | timestamp | 创建时间 |
| `updated_at` | timestamp | 更新时间 |

说明：密码、salt、账号状态属于认证凭据，不放在 `person` 表。`person` 只表示业务人员身份。

### organization

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | integer | 数字主键 |
| `oid` | varchar | 组织英文标识，唯一，规则同 `person.pid`，例如 `wei` |
| `name` | varchar | 展示名，例如 `魏国` |
| `type` | varchar | 空间类型，例如 `company` / `home` / `family` / `person` / `school` |

### membership

沿用现有表：

| 字段 | 说明 |
|------|------|
| `person_id` | 数字外键，指向 `person.id` |
| `organization_id` | 数字外键，指向 `organization.id` |
| `role` | 用户在组织中的角色 |

注意：`person.pid` / `organization.oid` 是字符串业务标识；除 `person` / `organization` 外，其余表的关联字段统一改为 `person_id` / `organization_id`。

---

## 2. 字段命名约定

- `person.id`：人员数字主键。
- `person.pid`：人员业务标识，英文非特殊字符，例如 `caocao`。
- `organization.id`：组织数字主键。
- `organization.oid`：组织业务标识，规则同 `pid`，例如 `wei`。
- 除 `person` / `organization` 两张主表外，其他表的外键统一使用 `person_id` / `organization_id`，不得再使用 `pid` / `oid` 表示数字外键。

需要调整的表包括但不限于：

| 表 | 旧字段 | 新字段 |
|----|--------|--------|
| `membership` | `pid`, `oid` | `person_id`, `organization_id` |
| `resource` | `oid`, `pid` | `organization_id`, `person_id` |
| `warehouse` | `oid` | `organization_id` |
| `transaction` | `oid` | `organization_id` |
| `party` | `pid`, `oid` | `person_id`, `organization_id` |

---

## 3. 登录名规则

用户登录名格式：

```text
{person.pid}@{organization.oid}.cn
```

示例：

```text
caocao@wei.cn
```

解析结果：

```json
{
  "pid": "caocao",
  "oid": "wei"
}
```

当前版本仅支持 `.cn` 后缀。

## 4. 用例一：用户注册

### 目标

新用户注册为 `person`，并加入指定组织空间，形成 `membership`。

### API

```http
POST /auth/register
```

### Request

```json
{
  "login": "caocao@wei.cn",
  "password": "demo123",
  "name": "曹操",
  "role": "主公"
}
```

### 业务流程

1. 校验 `login` 格式必须为 `{pid}@{oid}.cn`。
2. 校验 `pid` 和 `oid` 只能包含英文、数字、下划线、短横线。
3. 查询 `organization.oid = oid`。
4. 如果组织不存在，返回 404。
5. 查询 `person.pid = pid`。
6. 如果 person 不存在，创建 person：
   - `pid = pid`
   - `name = request.name`
7. 如果 person 已存在，继续使用该 person，但不得覆盖 `name`，除非后续另有资料维护接口。
8. 查询 `account.login = login`。
9. 如果 account 不存在，创建 account：
   - `person_id = person.id`
   - `login = request.login`
   - `password` 使用 Argon2 encoded hash；如 Argon2 接入困难，允许临时使用 bcrypt。
   - `salt` 如由 Argon2 encoded hash 内置保存，可为空；如果使用自管 salt，则写入该字段。
10. 如果 account 已存在：
   - 必须属于同一个 `person_id`。
   - 校验密码；密码不匹配返回 409。
11. 查询 `membership(person_id=person.id, organization_id=organization.id)`。
12. 如果 membership 不存在，创建 membership，role 使用 request.role，默认 `member`。
13. 返回注册结果和登录上下文。

### Response

```json
{
  "person": {
    "id": 8,
    "pid": "caocao",
    "name": "曹操"
  },
  "organization": {
    "id": 2,
    "oid": "wei",
    "name": "魏国",
    "type": "company"
  },
  "account": {
    "id": 1,
    "login": "caocao@wei.cn",
    "status": "active"
  },
  "membership": {
    "role": "主公"
  }
}
```

### 验收标准

- `newuser@wei.cn / demo123` 注册成功，创建 person 和 membership。
- `caocao@unknown.cn` 注册失败，组织不存在。
- `曹操@wei.cn` 注册失败，pid 非法。
- `caocao@wei.org` 注册失败，当前只支持 `.cn`。
- 重复注册同一 person 到同一 org 不应重复创建 membership。
- 注册成功后，密码只允许出现在 `account.password` 中，不允许写入 `person`。

## 5. 用例二：用户登录

### 目标

用户通过 `person.pid@organization.oid.cn` 和密码登录，系统返回 JWT 和当前组织上下文。

### API

```http
POST /auth/login
```

### Request

```json
{
  "login": "caocao@wei.cn",
  "password": "demo123"
}
```

### 业务流程

1. 校验 `login` 格式。
2. 解析 `pid` 和 `oid`。
3. 查询 `account.login = login`。
4. 如果 account 不存在，返回 401。
5. 确认 `account.status = active`，否则返回 403。
6. 通过 `account.person_id` 查询 person，并校验 `person.pid = pid`。
7. 查询 `organization.oid = oid`。
8. 查询 membership：

```sql
SELECT role
FROM membership
WHERE person_id = :person_id
  AND organization_id = :organization_id;
```

9. 校验 `account.password`。
10. 成功后签发 JWT。
11. 返回 token 和登录上下文。

### JWT payload

JWT 只放业务字段，不夹杂数据库数字主键。

```json
{
  "pid": "caocao",
  "person_name": "曹操",
  "oid": "wei",
  "organization_name": "魏国",
  "organization_type": "company",
  "role": "主公"
}
```

### Response

```json
{
  "access_token": "...",
  "token_type": "bearer",
  "person": {
    "id": 8,
    "pid": "caocao",
    "name": "曹操"
  },
  "organization": {
    "id": 2,
    "oid": "wei",
    "name": "魏国",
    "type": "company"
  },
  "account": {
    "id": 1,
    "login": "caocao@wei.cn",
    "status": "active"
  },
  "membership": {
    "role": "主公"
  }
}
```

### 验收标准

- `caocao@wei.cn / demo123` 登录成功，JWT 返回 `pid=caocao`、`oid=wei`。
- `caocao@shu.cn / demo123` 登录失败，因为 membership 不存在。
- `caocao@wei.cn / wrong` 登录失败，返回 401。
- `account.status != active` 登录失败，返回 403。
- `caocao@unknown.cn / demo123` 登录失败。
- `曹操@魏国.cn / demo123` 登录失败。
- 登录成功后，前端上下文必须使用 token 中的业务字段 `oid`，不能手动访问未授权组织。

## 6. 开发任务

### DBA

1. 在 `person` 表增加：
   - `pid VARCHAR(100)`
2. 在 `organization` 表增加：
   - `oid VARCHAR(100)`
3. 新增 `account` 表：
   - `id SERIAL PRIMARY KEY`
   - `person_id INTEGER NOT NULL REFERENCES person(id) ON DELETE CASCADE`
   - `login VARCHAR(150) NOT NULL UNIQUE`
   - `password TEXT NOT NULL`
   - `salt TEXT`
   - `status VARCHAR(30) NOT NULL DEFAULT 'active'`
   - `created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP`
   - `updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP`
4. 增加唯一索引：
   - `person.pid`
   - `organization.oid`
   - `account.login`
5. 更新 `scripts/init_db.py`，写入样例账号：

```text
liubei@shu.cn / demo123
caocao@wei.cn / demo123
sunquan@wu.cn / demo123
zhugeliang@shu.cn / demo123
```

### Backend

1. 在 `src/auth/auth.py` 补齐密码哈希和 JWT 工具函数，优先使用 Argon2。
2. 在 `src/db/database.py` 增加认证相关查询函数。
3. 在 `src/app.py` 增加：
   - `POST /auth/register`
   - `POST /auth/login`
4. 登录和注册必须通过 `membership` 做组织授权。
5. 认证相关查询必须读取 `account`，不得从 `person` 读取密码。

### Frontend

1. 增加登录表单：
   - login: `caocao@wei.cn`
   - password
2. 登录成功后保存：
   - `access_token`
   - `oid`
   - `organization_name`
3. 所有后续请求使用登录态中的业务字段 `oid`。
