# Uni-Resource Agent 改进方案

## 1. 现状分析

### 当前系统架构
- 四种资源类型：物理资产、知识、人员、财务
- 数据库采用 PostgreSQL + ChromaDB
- 工具函数通过 `@tool` 装饰器包装，由 LangChain Agent 使用
- 所有数据访问基于 `ouid` (组织) + `puid` (人员) 上下文隔离

### 当前工具函数
- 资源相关：`query_resource_tool`, `query_resource_stock`（模拟了 `query_asset`）
- 财务相关：`record_transaction`, `get_transaction_history`, `get_summary`
- 人员相关：`manage_reminder`, `check_wellness`
- 知识相关：`rag_search`, `store_knowledge`

### 缺失功能
- 未实现 `transfer_asset` 工具函数
- 实现逻辑未完全按照 AGENTS.md 中的接口定义

## 2. 改进模式分析

### 改进模式一："物流变成信息流"
- **现状**：物理资产的转移涉及实际物流运输
- **改进**：通过数据记录实现资产转移逻辑，信息流替代物理流
- **实施**：为 `transfer_asset` 实现数据处理逻辑，将资产从一个组织转移到另一个组织，通过数据库更新操作

### 改进模式二："改善信息流转"
- **现状**：信息在不同系统或组件间流转存在延迟和不一致
- **改进**：通过统一上下文（`ouid`, `puid`）实现信息一致流转
- **实施**：在所有工具函数中，通过上下文参数确保所有数据库操作都使用正确的 `ouid` 和 `puid`，实现数据隔离和一致性

### 改进模式三："封装领域逻辑"
- **现状**：业务逻辑分散在多个地方
- **改进**：将领域逻辑封装在工具函数中，使调用者只需关注业务需求
- **实施**：实现完整的 `transfer_asset` 工具函数，封装资产转移的业务逻辑

"""Asset tools: query_asset, transfer_asset."""
from typing import Optional
from langchain_core.tools import tool
import json

from src.db.database import (
    query_asset,
    transfer_asset_db,
    resolve_organization_id,
)


@tool
def query_asset(name: str, ouid: str = "shu", warehouse: Optional[str] = None) -> str:
    """
    Query asset information by name.

    Args:
        name: Name of the asset to query (partial match supported).
        ouid: Organization business identifier, e.g. "shu".
        warehouse: Warehouse filter (optional).
    """
    try:
        organization_id = resolve_organization_id(ouid)
        results = query_asset(organization_id, name=name, warehouse=warehouse)
        if results:
            return json.dumps(results, default=str, ensure_ascii=False)
        return f"No asset found matching '{name}' in org {ouid}"
    except Exception as e:
        return f"Error querying assets: {e}"


@tool
def transfer_asset(asset_id: int, from_ouid: str, to_ouid: str, quantity: int) -> str:
    """
    Transfer an asset from one organization to another.

    Args:
        asset_id: ID of the asset to transfer.
        from_ouid: Source organization business identifier.
        to_ouid: Destination organization business identifier.
        quantity: Quantity to transfer.
    """
    try:
        from_org_id = resolve_organization_id(from_ouid)
        to_org_id = resolve_organization_id(to_ouid)
        
        # Call database function to perform the transfer
        result = transfer_asset_db(asset_id, from_org_id, to_org_id, quantity)
        return json.dumps(result, default=str, ensure_ascii=False)
    except Exception as e:
        return f"Error transferring asset: {e}"
```

# 在现有函数之后添加
def transfer_asset_db(asset_id: int, from_org_id: int, to_org_id: int, quantity: int) -> Dict[str, Any]:
    """
    Transfer an asset from one organization to another at the database level.
    
    Args:
        asset_id: ID of the asset to transfer.
        from_org_id: Source organization ID.
        to_org_id: Destination organization ID.
        quantity: Quantity to transfer.
        
    Returns:
        Dict with transfer result details.
    """
    conn = None
    try:
        conn = get_db_connection()
        cur = conn.cursor(cursor_factory=RealDictCursor)
        
        # Check if the asset exists and belongs to from_org
        cur.execute(
            "SELECT * FROM resource WHERE id = %s AND organization_id = %s",
            (asset_id, from_org_id)
        )
        asset = cur.fetchone()
        if not asset:
            raise ValueError(f"Asset {asset_id} not found or does not belong to organization {from_org_id}")
        
        # Check if the asset has sufficient quantity in warehouse
        cur.execute(
            "SELECT SUM(quantity) as total FROM resource_warehouse WHERE resource_id = %s",
            (asset_id,)
        )
        total_qty = cur.fetchone()["total"]
        if not total_qty or total_qty < quantity:
            raise ValueError(f"Insufficient quantity for asset {asset_id}. Available: {total_qty}, requested: {quantity}")
        
        # Create transaction record
        cur.execute(
            "INSERT INTO transaction (amount, category, description) VALUES (%s, %s, %s) RETURNING id",
            (quantity, "asset_transfer", f"Transfer of asset {asset_id} from org {from_org_id} to {to_org_id}")
        )
        transaction_id = cur.fetchone()["id"]
        
        # Create party records for both organizations
        cur.execute(
            "INSERT INTO party (organization_id, transaction_id, name, role, description) VALUES (%s, %s, %s, %s, %s)",
            (from_org_id, transaction_id, f"From Org {from_org_id}", "payer", f"Asset transfer out")
        )
        
        cur.execute(
            "INSERT INTO party (organization_id, transaction_id, name, role, description) VALUES (%s, %s, %s, %s, %s)",
            (to_org_id, transaction_id, f"To Org {to_org_id}", "payee", f"Asset transfer in")
        )
        
        # Perform the actual asset transfer in warehouse
        # This is a simplified version - in reality you might need more complex logic
        # to handle different warehouse locations
        cur.execute(
            "UPDATE resource_warehouse SET quantity = quantity - %s WHERE resource_id = %s AND quantity >= %s",
            (quantity, asset_id, quantity)
        )
        
        # Add new warehouse entry for destination org if needed (simplified)
        # In reality, you would need to determine the proper location
        cur.execute(
            "INSERT INTO resource_warehouse (resource_id, location_path, quantity, unit) VALUES (%s, %s, %s, %s)",
            (asset_id, "default_destination", quantity, asset.get("unit", "unit"))
        )
        
        conn.commit()
        
        return {
            "success": True,
            "message": f"Asset {asset_id} transferred from {from_org_id} to {to_org_id}",
            "transaction_id": transaction_id
        }
    except Exception as e:
        if conn:
            conn.rollback()
        raise e
    finally:
        if conn:
            conn.close()
```
