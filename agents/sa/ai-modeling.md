# Uni-Resource Agent 建模

基于对项目需求和UML建模方法的理解，我将为Uni-Resource Agent项目进行系统建模。根据项目文档，这是一个多上下文AI代理系统，管理不同身份（如工作、家庭、学校）的资源。系统支持四种资源类型：物理资源、知识资源、人员资源和财务资源。

## 1. 愿景定义

### 1.1 系统
Uni-Resource Agent是一个多上下文AI代理系统，能够管理用户在不同身份（工作、家庭、学校、个人）下的各种资源。

### 1.2 目标组织
目标组织是需要管理多身份资源的个人用户，包括但不限于：
- 企业员工
- 家庭成员
- 学生
- 自由职业者

### 1.3 老大
目标组织的代表是个人用户，他们需要在不同身份间切换并管理各自资源。

### 1.4 目标（度量指标）
- 提高个人资源管理效率
- 减少在不同身份间切换时的资源管理成本
- 实现跨身份资源的统一管理
- 降低资源管理的复杂度

## 2. 业务用例图

### 2.1 业务执行者
- 用户：系统的主要交互对象
- 系统：提供资源管理服务的AI代理

### 2.2 业务用例
- 管理物理资源：查询、转移、记录资产
- 管理知识资源：知识搜索、文档管理
- 管理人员资源：提醒管理、健康追踪
- 管理财务资源：记录交易、查询余额
- 切换身份上下文：在不同身份间切换

## 3. 业务序列图

### 3.1 现状业务序列图
1. 用户使用系统
2. 系统识别用户身份
3. 系统根据身份加载对应上下文
4. 用户执行资源管理操作
5. 系统在对应上下文中处理请求
6. 系统返回处理结果

### 3.2 改进业务序列图
1. 用户使用系统
2. 系统识别用户身份
3. 系统根据身份加载对应上下文
4. 用户执行资源管理操作
5. 系统在对应上下文中处理请求
6. 系统返回处理结果
7. 系统记录操作日志

## 4. 系统用例图

### 4.1 系统执行者
- 用户：系统的主要执行者
- 数据库：系统后台数据存储
- 外部系统：提供外部数据支持

### 4.2 系统用例
- 查询资产：查询物理资产信息
- 转移资产：在不同身份间转移资产
- 记录交易：记录财务交易信息
- 管理提醒：设置和管理提醒事项
- 知识搜索：通过RAG搜索知识资源
- 切换身份：在不同身份上下文间切换
- 系统管理：管理系统的配置和设置

## 5. 系统用例规约

### 5.1 查询资产用例
- 执行者：用户
- 前置条件：用户已登录系统
- 后置条件：系统返回资产信息
- 涉众利益：用户需要了解资产状态
- 基本路径：
  1. 用户请求查询资产
  2. 系统验证用户身份
  3. 系统查询当前上下文的资产
  4. 系统返回资产信息
- 扩展路径：
  1. 用户未登录：系统提示登录
  2. 无资产信息：系统返回无资产提示

### 5.2 转移资产用例
- 执行者：用户
- 前置条件：用户已登录系统
- 后置条件：资产成功转移
- 涉众利益：用户需要在不同身份间转移资源
- 基本路径：
  1. 用户请求转移资产
  2. 系统验证用户身份
  3. 系统验证资产转移的合法性
  4. 系统执行资产转移
  5. 系统返回转移结果
- 扩展路径：
  1. 资产不足：系统提示资产不足
  2. 转移失败：系统提示转移失败原因

### 5.3 记录交易用例
- 执行者：用户
- 前置条件：用户已登录系统
- 后置条件：交易信息记录成功
- 涉众利益：用户需要记录财务信息
- 基本路径：
  1. 用户请求记录交易
  2. 系统验证用户身份
  3. 系统记录交易信息
  4. 系统返回记录结果
- 扩展路径：
  1. 交易信息错误：系统提示错误并要求重新输入

## 6. 分析类图

### 6.1 核心域类
- Agent：代理核心类
- Context：上下文类
- Asset：资产基类
- PhysicalAsset：物理资产类
- VirtualAsset：虚拟资产类
- Personnel：人员类
- Transaction：交易类
- User：用户类

### 6.2 关联关系
- User与Context：一对多关联
- Context与Asset：一对多关联
- Asset与Transaction：一对多关联
- Context与Personnel：一对多关联
- Agent与Context：聚合关系
- Agent与User：关联关系

## 7. 设计模式应用

### 7.1 人员管理模式
- 人员信息通过联系方式关联
- 联系方式类型和用途分离
- 人员关系通过自反关联表达

### 7.2 资源管理模式
- 资源按类型分层管理
- 通过上下文隔离不同身份的资源
- 资源操作遵循统一的接口规范

## 8. 系统架构设计

### 8.1 系统组件
- 用户接口层：提供用户交互界面
- 代理核心层：处理业务逻辑
- 数据访问层：访问数据库和外部资源
- 数据存储层：存储各种资源信息

### 8.2 数据流
1. 用户请求通过接口层进入系统
2. 代理核心层分析请求并确定操作类型
3. 数据访问层根据操作类型访问对应数据存储
4. 系统返回处理结果给用户
