## 3. 已知问题与处置（重要）

### 3.1 ⚠️ DB 种子数据会被 test_three_kingdoms.py 清空

**根因**：`test_three_kingdoms.py` 的 fixture 调用 `init_database(drop_all=True)`，会 DROP 全库表并只重建三国数据。该文件在文件名的字母序中排在最后，**每次全量跑完，DB 里的 demo 种子数据（zhansan / liuming）都会消失**。

**现象**：全量回归后 `test_demo_smoke.py` / `test_recording_smoke.py` 登录报 401 `Invalid credentials`，因为 `zhansan`/`liuming` 账号不存在。

**处置**：跑 demo/recording 冒烟前必须先补种：

```bash
PYTHONPATH=. python scripts/seed_demo_data.py      # 需要 .env 的 DEMO_ZHANSAN_PASSWORD
PYTHONPATH=. python scripts/seed_recording_data.py # 需要 .env 的 DEMO_LIUMING_PASSWORD
```

两个脚本均幂等（重跑 0 新增）。`DEMO_ZHANSAN_PASSWORD` / `DEMO_LIUMING_PASSWORD` 均在仓库 `.env`（gitignored）中，已确认存在。

**建议运行顺序**（避免互相污染）：
1. 先跑 `test_three_kingdoms.py` / `test_three_kingdoms_http.py`（会清库，放最后）。
2. 再补种 demo/recording 数据。
3. 最后跑 demo/recording 冒烟。

### 3.2 LLM 时序抖动：test_three_kingdoms_http 的 chat 用例

- 失败用例：`TestChatAPI::test_chat_with_context`、`TestIntegration::test_full_workflow`。
- 现象：`/chat` 在 30s 超时后返回 504（`Chat request timed out`），但 Agent 实际已完成并输出结果，只是整体耗时 >30s。
- 性质：**真 LLM 延迟抖动，与连接池无关**（测试自身断言就容忍 `(200, 500, 503)`；504 是 FastAPI 30s 超时）。已有先例：Playwright test_05 曾一次 timing rerun 后绿。
- 处置：重跑一次即可；若持续超时，检查本地 LLM 后端（llama.cpp / Qwen）是否已加载。

### 3.3 安全扫描要点（PERF-01 红线）

- 聚合响应不得含 DB 数字 ID、不得含 `pid/oid`。
- 聚合接口拒绝身份 query 参数（`id/puid/ouid/person_id/organization_id/resource_id/warehouse_id` → 400）。
- `/seller/workbench` 非 ecommerce 空间 → 403；不触发 LLM。
- 默认测试不触发真 LLM（`test_seller_chat_live_llm.py` 除外，不参与默认运行）。
- `profile.yaml` 不得含密码；密码只走环境变量/`.env`。

## 5. 测试场景与脚本编写经验（TDD 约定）

> 详细规范见 `agents/tdd/TDD_AGENT.md`、`agents/tdd/DEMO_双场景回归测试计划.md`。

### 5.1 编写测试用例的既有约定

1. **黑盒测试**：测试不修改 `src/` 代码，全部通过 HTTP API（`fastapi.testclient.TestClient`）访问。
2. **上下文隔离**：每个测试用独立 `ouid + puid`（或独立账号），不依赖彼此留下的数据；Demo 冒烟则在固定种子账号（zhansan / liuming）之上验证，见 §3.1。
3. **TDD 红绿循环**：先写用例并**确认它失败**（原因必须是"功能缺失"，不是笔误），再写最小实现让它通过，最后重构。测试通过即"发现不是 bug"的情形要警惕。
4. **用例命名**：`test_<场景>_<预期>`，一个用例只测一件事（名字里不要出现 "and"）。
5. **安全红线即断言**：`_FORBIDDEN_ID_FIELDS = {"id","pid","oid","person_id","organization_id","membership_id","resource_id","warehouse_id","transaction_id","account_id","resource_warehouse_id","inventory_movement_id"}`，对每个响应做**递归键扫描**（`_assert_no_internal_keys` / `assertNoDbIdKeys`），任何 `_id` / `pid` / `oid` 一出现就 FAIL。
6. **身份字段规则**：对外只有 `puid/ouid/product_uid/warehouse_code/movement_uid/transaction_uid/campaign_code`；`person_id`/`organization_id` 等 DB 数字 PK 仅限内部使用，禁止出 API。

### 5.2 默认测试不触发真 LLM

- 默认 `pytest` 不能依赖真 LLM。规则：
  - `/seller/chat` 测试用脚本化 fake LLM（fake 只发出 `seller_stock` 等工具调用 → 真实工具查真实 DB → fake 从真实结果归纳回答）。
  - 新增"连真 LLM"的测试必须**独立文件/独立 marker**（如 `test_seller_chat_live_llm.py`），不进默认收集。
- 这样即使本地 llama.cpp 没起，`test_demo_smoke.py` / `test_recording_smoke.py` / `test_seller_chat_api.py` 仍能稳定运行。

### 5.3 连接真实 DB 的测试依赖

- 大部分回归测试（auth/seller/spaces）**自建数据**，跑完不清理也不影响彼此（用随机 uuid）。
- 只有 Demo 冒烟依赖固定种子（`seed_demo_data.py` 的 zhansan / `seed_recording_data.py` 的 liuming）。
- 种子密码只从环境变量/`.env` 读取；模块顶部 `if not PASSWORD: pytest.skip(...)` 或 `pytest.exit(...)`，**绝不写死密码**。

### 5.4 测试脚本组织建议

- API 级契约/回归 → `agents/tdd/test_*.py`（TestClient）。
- 单测级（无 DB，monkeypatch）→ 独立文件如 `test_perf01_aggregate_and_pool.py`（保证默认跑得快、可离线）。
- 配置测试（`test_config.py`）可注入 `profile_file` / monkeypatch 环境变量，不触碰真实 `.env`。
- E2E/录屏 → `agents/tdd/playwright/`（独立目录、独立 requirements、`-m recording` marker）。

## 6. Playwright 端到端测试经验

> 目录：`agents/tdd/playwright/`；运行说明见 `playwright/README.md`。

### 6.1 基础设施（conftest.py）

- `sync_playwright` + chromium，`--headed`（有头，用于录屏）与 `--slowmo`（毫秒）通过 pytest 选项控制。
- 视口固定 `1440x900`，`record_video_dir=videos/`（**WebM 自动产出**），`ignore_https_errors=True`。
- `browser_context` fixture 注册 `context.route("**/*", audit_route)`：对 `/auth/` 与 `/seller/` 前缀的请求打印 `[api-audit] METHOD url body=...`，POST body 中的 `password/access_token/token` **递归脱敏**（`<redacted>`），防录屏日志泄密。
- 超时：页面默认 10s、导航 15s。

### 6.2 用例编写要点（test_demo_recording.py）

1. **单用例主流程**：录屏用例 `test_recording_main_flow` **只登录一次**，靠 Header 切换空间走完整流程——避免多次登录打断录屏节奏。
2. **`data-test` 定位**：所有断言用 `[data-test="..."]` 或 `get_by_role`，不用脆弱的文本/CSS 路径（登录表单、app-header、workbench、generic-space、stock-view、metric-sales、org-switch、chat-input 等均为 `data-test`）。
3. **`_switch_org` 校验后端契约**：用 `page.expect_request(lambda req: ... path == "/auth/switch-organization")` 捕获请求，断言 body **只含 `{ouid}`**，且对 body 做 `_assert_no_internal_keys`。
4. **等待加载完成**：`locator.wait_for(state="visible", timeout=10_000)`；AI 回复类用 `expect(...).to_contain_text(re.compile(...), timeout=30_000)`。
5. **`_hold(page)` 停屏**：每屏数据出现后 `wait_for_timeout(HOLD_MS)`（默认 4000ms），供录屏观众看清数据，`E2E_HOLD_MS` 可调。
6. **fake chat 开关**：`E2E_FAKE_SELLER_CHAT=1` 时 `page.route` 拦截 `/seller/chat` 返回固定答案（绕过真 LLM），正式验收建议关闭。
7. **环境变量**：`E2E_BASE_URL`(5173) / `E2E_API_BASE`(8000) / `DEMO_RECORDING_*` / `E2E_HOLD_MS`；密码从 `.env` 读，缺密码 `pytest.exit`。

### 6.3 运行与稳定性

```bash
bash agents/tdd/playwright/run_recording.sh   # 等价于 pytest -m recording -v --headed --slowmo=500 --reruns 1
```

- 建议带 `--reruns 1`（时间抖动重试，已有 test_05 / chat 先例）。
- 前置：后端 :8000、前端 :5173、`seed_recording_data.py` 已跑、密码可用。
- 产物：`videos/page@*.webm`；`videos/`、`test-results/` 已 gitignore。

## 7. 录屏技能与经验（Demo 录制）

### 7.1 录屏前必须就绪

1. **数据**：DB 里必须有录屏账号数据（`seed_recording_data.py` → liuming）。**注意**：只要跑过 `test_three_kingdoms.py`（drop_all），数据就被清掉，必须先重新补种（§3.1）。
2. **服务**：后端 `:8000`、前端 `:5173` 都活，`/health` 返回 ok；live 后端每次改 `src/` 代码后要手动重启（无 `--reload`）。
3. **性能**：录屏前先跑性能验收（workbench <1.5s、dashboard <2.0s），避免录屏中出现等待/白屏；真 LLM 慢不在本轮验收范围，可临时 `E2E_FAKE_SELLER_CHAT=1`。
4. **隐私**：录屏演示账号密码绝不写进代码/文档/脚本，只放 `.env`；request audit 已对敏感字段脱敏。

### 7.2 录屏节奏控制（让观众能看懂）

- 每屏数据加载后停留 ≥4s（`E2E_HOLD_MS=4000`，重要屏可调大到 6-8s）。
- 全程**只登录一次**，用 Header 切换空间，天然演示多空间隔离与上下文随动。
- 录屏主流程话术（来自 playwright/README.md）：
  - 登录 liuming → 自动进入个人空间："用一个账号登录，系统自动进入刘明自己的个人工作空间。"
  - Header 无 AI 输入框："顶部只显示用户、个人空间、类型和角色，AI 入口收归在工作台内。"
  - 切电商 → 6 商品/低库存标签/摘要/Seller AI："AI 指出最低库存是草船借箭纪念徽章（3枚）。"
  - 切战役复盘 → 8 条时间线 + 信息流/物流/人流："前端停止调用 Seller 接口，数据互不串扰。"
  - 切回电商："仍无需重新登录，多空间数据互不串扰。"
